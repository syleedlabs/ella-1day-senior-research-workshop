사용자가 만들고 싶은 것이 있으나 요구사항이 정리되지 않은 상태다. **바로 만들지 않는다.**

## 진행

1. 먼저 확인한다 — "무엇을 만들고 싶으신지 한 줄로만 말씀해 주세요. 나머지는 제가 여쭤볼게요."
2. **한 번에 하나씩** 물어본다. 여러 질문을 한꺼번에 던지지 않는다.
   질문은 아래 축을 중심으로, 대화 흐름에 맞게 고른다.
   - **목적** — 이걸로 무엇을 해결하고 싶으신가요?
   - **입력** — 무엇을 주면 되나요?
   - **출력** — 결과가 어떤 모양이면 좋겠어요? 파일로 저장할까요, 화면에만?
   - **빈도** — 얼마나 자주 쓰실 것 같아요?
   - **품질 기준** — 어떤 결과가 나오면 "잘 됐다"고 느끼실까요?
   - **하지 말아야 할 것** — 절대 안 했으면 하는 게 있나요?
3. 질문은 **5~7개 안쪽**으로 끝낸다. 사용자를 지치게 하지 않는다.
4. 다 이해했다 싶으면 **요약해서 확인받는다.**

```
정리하면 이렇습니다.
  · 만들 것:
  · 입력:
  · 출력:
  · 품질 기준:
  · 하지 않을 것:

이대로 진행할까요? 고칠 부분 있으면 말씀해 주세요.
```

5. **확인받은 뒤에** 만들기 시작한다.

## 왜 이렇게 하나

토큰을 가장 많이 먹는 건 긴 프롬프트가 아니라 **재작업**이다.
길게 설명 → 엉뚱하게 만듦 → 다시 설명 → 또 만듦, 이 루프가 비싸다.
앞단의 짧은 질답 몇 번이 이 루프 전체를 없앤다.

## 잊지 말 것

- 사용자가 이미 명확히 말씀하신 건 **다시 묻지 않는다.**
- 질문에 "왜 묻는지"를 한 줄 곁들이면 답하기 쉬워진다.
- 사용자가 "그냥 만들어줘"라고 하면 인터뷰를 멈추고 만든다.
