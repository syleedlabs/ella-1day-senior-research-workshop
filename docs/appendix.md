## B. 봇을 이루는 .md 파일들 {#md-hierarchy}

봇은 하나의 파일이 아니라 **여러 마크다운 파일의 협업**으로 움직여요. 각 파일이 무슨 역할이고 언제 읽히는지 알면, 봇을 고칠 때 "어디를 고쳐야 하지?"가 명확해집니다.

### B-1. 파일과 역할

| 파일 | 범위 | 역할 | 언제 읽히나 |
|---|---|---|---|
| `CLAUDE.md` | 프로젝트 전체 | 늘 지켜야 할 규칙 — 출처 표기·미확인 라벨·비교 축 (가장 큰 틀) | 항상 |
| `.claude/agents/senior-compare-kr-global.md` | 비교 브리프 | 국내·해외 조사와 시차 해석 방식 | 그 에이전트로 일할 때 |
| `.claude/agents/senior-biz-idea.md` | 기회 카드 | 조사 결과를 사업 언어로 옮기는 방식 | 〃 |
| `.claude/agents/senior-weekly-news.md` | 주간 리포트 | 한 주 흐름을 훑고 묶는 방식 | 〃 |
| `.claude/commands/*.md` | 이 커맨드 | **슬래시 커맨드** — 부르면 해당 에이전트로 전환 | 그 커맨드를 부를 때 |

> `CLAUDE.md`가 무엇이고 어떻게 활용하는지는 [2-2 PRD 설계도](/part2/2-2-prd)에 정리했어요. 여기서는 **뭘 고칠 때 어느 파일을 여는지**만 봅니다.

### B-2. 큰 틀 → 작은 틀 (하이어라키)

```
CLAUDE.md                    ← 프로젝트 상시 규칙 (항상 적용, 가장 넓음)
  └ .claude/agents/          ← 에이전트 (이 봇은 무슨 일을 어떻게 하나)
       └ .claude/commands/   ← 커맨드 (지금 이 순간 무엇을 부르나)
```

큰 틀이 작은 틀을 감싸요. `CLAUDE.md`의 규칙(출처 표기·미확인 라벨)이 늘 배경에 깔리고, 그 위에서 **에이전트**가 "무슨 일을 어떤 형식으로 하는가"를 정하고, **커맨드**가 그 에이전트를 불러옵니다.

### B-3. 그래서 고칠 때 — 어디를 여나 {#b3}

| 바꾸고 싶은 것 | 고치는 파일 |
|---|---|
| 출처 표기 규칙·미확인 라벨 (전체 공통) | `CLAUDE.md` |
| 비교 대상국 (일본·미국 → 다른 나라) | `CLAUDE.md` + `senior-compare-kr-global.md` |
| 브리프 길이·구성 | `.claude/agents/senior-compare-kr-global.md` |
| 기회 카드 항목 구성 | `.claude/agents/senior-biz-idea.md` |
| 주간 리포트가 훑는 범위 | `.claude/agents/senior-weekly-news.md` |
| 조사 소스 목록 | `CLAUDE.md`의 소스 섹션 |

::: tip 직접 편집하지 않으셔도 돼요
파일을 열어 고치는 건 클로드 코드가 합니다. 나리님은 **뭘 바꾸고 싶은지 말씀만** 하시면 돼요.

```
브리프가 너무 길어. 국내·해외 각각 3줄로 줄여줘.
```

위 표는 "지금 어디가 고쳐지고 있는지" 이해하시라고 정리한 거예요.
:::

## C. 워크숍 후 다음 단계 {#c-워크숍-후-다음-단계}

### C-1. ⭐ 주간 리포트 자동 실행 걸기 {#c1}

[2-3](/part2/2-3-harness)에서 본 **시간 기반 루프**를 실제로 거는 절차예요. 5분이면 됩니다.

**① 등록**

클로드 코드에 이렇게 입력하세요.

```
/schedule 매주 월요일 아침 8시에 /senior-weekly-news 를 실행해서
지난 한 주 국내외 시니어 시장 뉴스를 리포트로 정리해줘.
```

**② 확인**

인자 없이 치면 **등록된 루틴 목록**이 나와요. 방금 건 게 보이면 성공입니다.

```
/schedule
```

**③ 해제**

목록에서 해당 루틴을 골라 삭제하시면 돼요. **언제든 뺄 수 있으니** 부담 없이 걸어보세요.

::: tip 왜 `/loop`가 아니라 `/schedule`일까요
`/loop`는 **이 노트북에서** 돕니다. 월요일 아침 8시에 노트북이 켜져 있어야 해요.
`/schedule`은 **클라우드에서** 돕니다. 노트북을 닫아둬도 리포트가 만들어집니다.
:::

::: warning 걸기 전에 한 번 수동으로
자동으로 걸기 전에 `/senior-weekly-news`를 **한 번 직접 돌려보세요.** 결과가 마음에 드는지 먼저 확인하고 거는 게 안전합니다 — 2-3에서 본 "크게 돌리기 전에 파일럿"이에요.
:::

### C-2. 그다음 몇 주

- **1주차 — 딱 하나만.** 회의 전날 `/senior-compare-kr-global` 한 번. 이것만 손에 붙여도 충분해요.
- **1주차 월요일 — 자동 리포트 확인.** C-1로 걸어둔 리포트가 도착했는지 열어보세요.
- **2~3주차 — 소스·형식 손보기.** 몇 번 써보시면 "이건 빼고 싶다, 저건 더 봤으면" 하는 게 생겨요. 그때 [B-3](#b3)을 보고 말로 부탁하세요.
- **한 달 뒤 — 루프 확장.** [2-3](/part2/2-3-harness)의 ② 목표 기반이나 ④ 프로액티브가 필요해지는 순간이 옵니다. 그때 다시 열어보세요.

이번 주에 딱 한 번, 회의 전날 `/senior-compare-kr-global`을 불러보는 것부터 시작하세요.
:::
