## 1. 실무 팁 — 오래 쓸 프롬프트 {#practice-tips}

워크숍이 끝나고 **혼자 쓰실 때 꺼내 쓸 프롬프트들**입니다. 워크숍 중엔 안 다뤄도 되고, 필요해질 때 이 페이지를 열면 돼요.

### ⭐ "이해할 때까지 인터뷰해주세요" {#interview}

워크숍 밖에서 **가장 먼저 손에 붙이시면 좋은** 프롬프트예요.

나중에 "커맨드 하나 더 만들고 싶은데" 싶어지실 때가 옵니다. 그때 요구사항을 길게 설명하는 대신, **이렇게 시작하세요.**

```
바로 만들지 말고, 제가 뭘 원하는지 이해될 때까지 저를 인터뷰해주세요.
한 번에 하나씩 물어봐 주시고, 다 이해했다 싶으면
제 요구사항을 요약해서 확인받은 다음에 시작해주세요.
```

#### 왜 [토큰](/part1/1-1-intro#terms)이 절약되나

토큰을 가장 많이 먹는 건 긴 프롬프트가 아니라 **재작업**이에요.

```
❌ 요구사항을 길게 쏟아붓기
   길게 설명 → 엉뚱하게 만들어짐 → 다시 설명 → 또 만듦 → 또 다시…
   (매번 전체 결과물을 다시 생성 = 토큰 대량 소모)

⭕ 인터뷰로 시작하기
   짧은 질답 몇 번 → 요약 확인 → 한 번에 제대로 만들어짐
   (질답은 몇 줄짜리 = 아주 저렴)
```

앞단의 짧은 질답 몇 번이 뒤의 **재작업 루프 전체**를 없앱니다.

#### 왜 결과도 좋아지나

내가 미처 결정하지 못한 지점을 **클로드가 먼저 발견**해줘요. *"결과를 파일로 저장할까요, 화면에만 띄울까요?"* 같은 질문을 받으면, 답하면서 내 요구사항이 정리됩니다. 머릿속에 있던 게 말이 되는 거예요.

#### 언제 쓰나

- 새 커맨드나 에이전트를 만들고 싶을 때
- 요구사항이 머릿속에만 있고 말로 정리가 안 될 때
- "뭔가 만들고 싶은데 어디서부터 말해야 할지" 모를 때

::: tip 커맨드로도 심어뒀어요
```
/interview
```
매번 위 문장을 타이핑하지 않으셔도 됩니다.

**오늘은 돌리지 않으셔도 돼요.** 이건 실제로 뭔가를 만들기 시작하는 커맨드라, 워크숍 시간엔 맞지 않아요. 나중에 만들고 싶은 게 생겼을 때 꺼내 쓰시면 됩니다.
:::

::: tip 일을 넘기기 전에 기준부터
인터뷰는 에이전트에게 일을 넘기기 전에 **넘길 기준을 먼저 세우는 단계**예요. 무엇을 원하는지 스스로도 흐릿할 때, 클로드가 먼저 물어보게 하면 요구사항이 정리됩니다.
:::

### 실무에서 바로 쓸 수 있는 프롬프트 5가지

**1. 브리프가 그럴듯한데 미심쩍을 때**

```
이 브리프에서 가장 약한 근거가 뭐야? 나를 설득하려 하지 말고,
반대 입장에서 이 결론을 반박해봐.
```

**2. 숫자가 못 미더울 때**

```
이 수치의 원문(통계·보고서)까지 추적해서 기사 내용과 대조해줘.
단위랑 기준연도가 맞는지 특히 확인해줘.
```

**3. 조사할 게 많은데 뭐부터 볼지 모를 때**

```
시니어 시장 신사업을 검토하는 기획자로서, 아래 후보 주제들을
'근거 확보 난이도'와 '의사결정 임팩트' 두 축으로 정리해줘.
지금 당장 파야 할 3개를 순서대로 뽑아줘.
```

**4. 기획안에 넣기 전 마지막 점검**

```
이 내용을 임원 보고에 넣으려고 해. 반박당할 만한 지점을
심각도 순으로 정리하고, 각각 어떤 자료를 더 확보하면 되는지 알려줘.
```

**5. 에이전트가 느려지거나 파일이 지저분해졌을 때** ⭐

```
시니어 엔지니어로서 코드베이스를 리뷰해.
성능 병목, 중복, 접근성 이슈를 진단하고 리팩토링 계획을 잡아.
```

`.claude/` 안의 파일들이 늘어나면 **느려지고 서로 어긋나기 시작해요.** 이 한 줄이면 클로드 코드가 나리님의 에이전트 파일을 다 읽고, *어디서 시간이 새는지 · 같은 규칙이 몇 군데 중복됐는지 · 기다리는 사람이 답답한 지점은 어딘지* 를 짚어 **고칠 순서까지** 잡아줍니다.

::: tip 이 프롬프트가 특히 좋은 이유
**"고쳐줘"가 아니라 "진단하고 계획을 잡아"** 라고 시키는 게 핵심이에요. 바로 고치게 하면 뭘 왜 바꿨는지 모른 채 파일만 달라집니다. **먼저 계획을 받고 → 보고 나서 → 실행을 시키면** 나리님이 통제권을 쥔 채로 정리돼요.

`성능 병목 · 중복 · 접근성` 처럼 **볼 각도를 지정**한 것도 같은 이유입니다. *"좀 정리해줘"* 라고 하면 눈에 띄는 것만 손대거든요.
:::

::: tip 이 프롬프트들의 공통점
**역할을 명확히 지정**하고, **구체적인 산출물**을 요청합니다.

그리고 1·2·4번은 전부 **[2-4](/part2/2-4-harness)에서 본 Generator/Evaluator 분리를 프롬프트 레벨에서 쓰는 것**이에요. 만든 것을 그대로 믿지 않고, **검사하는 역할을 따로 불러오는** 겁니다.
:::

### 에이전트를 계속 키우는 3가지

| 방법 | 언제 | 어디가 바뀌나 |
|---|---|---|
| **조사 소스 추가** | 자주 보시는 매체·기관이 빠져 있을 때 | `CLAUDE.md`의 리서치 소스 우선순위 |
| **비교국 조정** | 대만·싱가포르 등 다른 나라를 보고 싶을 때 | `CLAUDE.md`의 비교 축 ([2-2](/part2/2-2-prd)) |
| **출력 형식 조정** | 브리프가 너무 길거나 짧을 때 | `agents/senior-compare-kr-global.md`의 출력 형식 |

**파일을 직접 여실 필요는 없어요.** 셋 다 클로드 코드에게 말로 부탁하시면 됩니다 — *"조사할 때 한국경제도 같이 보게 해줘"*, *"브리프를 지금보다 짧게 써줘"* 처럼요. 어느 파일을 고쳐야 할지는 클로드가 압니다.
