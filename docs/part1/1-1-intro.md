# 1-1. 클로드 코드란?

::: tip Step 1 / 8
시작하기 전에 두 가지만 잡고 가요. **클로드 코드가 ChatGPT와 뭐가 다른지**, 그리고 **오늘 이걸로 무엇을 만드는지**.
:::

## [개념] 클로드 코드란 무엇인가

한 문장으로 하면, 클로드 코드는 **나리님의 컴퓨터에서 파일과 명령을 직접 다루는 AI 동료**예요.

우리가 아는 챗봇은 화면 안에서 대화만 합니다. 아무리 좋은 답을 줘도, 그걸 실제 자료로 옮기는 건 결국 나리님 몫이었죠. 답을 복사해서 문서에 붙이고, 다시 물어보려고 자료를 붙여넣고 — 이 왕복을 하루에도 몇 번씩 반복하셨을 거예요.

클로드 코드는 이 왕복이 없어요. 대화로 시키면 **실제로 파일을 열어 읽고, 새 파일을 만들고, 고치고, 명령을 실행**합니다. "시니어 주거 시장을 국내·해외로 조사해서 정리해줘"라고 말하면, 결과를 화면에만 띄우는 게 아니라 나리님의 폴더 안에 **정리된 파일로 만들어** 둡니다.

::: tip 오늘 만드는 건 —
클로드 코드로 나리님이 오늘 손에 넣는 건 단순한 자동화 스크립트가 아니라 **시니어 시장을 대신 조사해주는 리서치 에이전트**예요. 프롤로그에서 본, 국내·해외를 교차해 브리핑하고 출처를 대던 그 에이전트가요. 정확히 무엇인지는 뒤 챕터에서 차근차근 짚어요. 지금은 "챗봇이 아니라 내 파일을 직접 다루는 동료"라는 감만 가져가시면 충분해요.
:::

## [개념] ChatGPT와 뭐가 다른가요?

| 기능 | ChatGPT | 클로드 코드 | 비고 |
|---|---|---|---|
| **파일 접근**<br>(File Access) | 불가 | 내 컴퓨터 파일을 직접 읽고 수정할 수 있음 | |
| **기억력**<br>(Memory) | 대화가 끝나면 사라짐 | 프로젝트 설정 파일에 저장해서 다음에도 기억함 | [2-3](/part2/2-3-claude-md) |
| **실행력**<br>(Execution) | 지시한 **작업**을 실행 | 지시한 **목표**를 달성 | |
| **동시 작업**<br>(Parallel) | 한 번에 하나씩 처리 | 여러 작업을 동시에 처리 가능 | |
| **에이전트**<br>(Agent) | 단일 인스턴스 | 역할별 전문 에이전트로 분업 가능 | [2-1](/part2/2-1-agents) |

각 기능을 좀 더 풀어볼게요.

**파일 접근 (File Access)** — ChatGPT는 대화창 안에서만 동작하지만, 클로드 코드는 내 컴퓨터의 폴더와 파일을 직접 다룰 수 있어요.

**기억력 (Memory)** — ChatGPT는 대화를 닫으면 이전 맥락을 잊지만, 클로드 코드는 `CLAUDE.md`라는 설정 파일에 프로젝트 정보를 저장해서 다음 대화에서도 기억해요.
(`CLAUDE.md`라는 메모리 파일에 저장합니다. [2-3](/part2/2-3-claude-md)에서 자세히 다룰 예정입니다.)

**실행력 (Execution)** — ChatGPT는 이메일 전송, 알람 생성처럼 지시한 단일 작업을 실행하지만, 클로드 코드는 지시한 목표를 스스로 분해하고 기획부터 구현까지 자동화해요.
예를 들어 *"시니어 주거 시장을 국내·해외로 비교해줘"* 라고 하면, 국내 조사 → 해외 조사 → 시차 해석 → 검수까지 스스로 판단하며 워크플로우를 구축합니다.

**동시 작업 (Parallel)** — ChatGPT는 하나의 요청을 순서대로 처리하지만, 클로드 코드는 여러 작업을 동시에 처리할 수 있어요.

**에이전트 (Agent)** — ChatGPT는 하나의 AI가 모든 것을 처리하지만, 클로드 코드는 기획·실행·검수처럼 역할별 전문 에이전트를 두고 분업할 수 있어요.
([2-1](/part2/2-1-agents)에서 에이전트 개념으로 자세히 다룰 예정입니다.)

::: tip 핵심 차이
ChatGPT도 실무에 활용할 수 있지만, 새 대화를 시작할 때마다 프로젝트 맥락, 선호사항, 용어 등을 **매번 다시 설명**해야 합니다. 이것을 **재설명 문제(Re-Explanation Problem)** 라고 해요.

클로드 코드는 `CLAUDE.md`에 이 정보를 저장해두기 때문에, 매번 처음부터 설명할 필요 없이 **바로 작업을 이어갈 수 있습니다.**
:::

## [개념] AI-Native 마인드셋

여기서 많은 분이 걱정하시는 게 있어요. "나는 코딩을 모르는데?" 그리고 "완벽한 명령어를 알아야 하는 거 아냐?"

두 가지 다 안 그래도 돼요. 오늘 필요한 태도는 딱 하나입니다.

> **완벽한 프롬프트를 미리 쓰려 하지 말고, 일단 대화로 시켜보고 · 결과를 보고 · 대화로 고친다.**

처음부터 완벽하게 시킬 필요가 없어요. "이렇게 해줘" → 결과 확인 → "음, 이 부분은 이렇게 바꿔줘" — 이 반복이 곧 작업이에요. 틀려도 괜찮습니다. 되돌리고 다시 말하면 되니까요. 나리님이 평소 사람 동료에게 일을 부탁하고 피드백하시던 그 방식 그대로예요.

### 마인드셋 전환

| | 기존 방식 | AI-Native 방식 |
|---|---|---|
| **사고방식** | *"프로그래밍 언어를 배우고, 라이브러리를 익혀서 직접 구현해야 해"*<br>*"GPT 프롬프트를 잘 써야 좋은 결과가 나와"* | *"목적을 명확하게 전달하고, 역할을 분담시키면 AI가 구현해줘"* |
| **구현 방식** | 사람이 코드를 한 줄씩 작성<br>프롬프트를 반복 수정하며 결과물 추출 | AI 에이전트가 **기획부터 구현까지** 자동으로 수행 |
| **학습 내용** | Python, JavaScript 등 코딩 언어 학습<br>GPT 프롬프트 작성법 공부 | 원하는 결과를 **정확하게 설명하는 방법**<br>AI에게 **역할을 나눠주는 방법** |

이 워크숍에서 배울 것은 **코딩이 아니에요.** 목적을 명확하게 정의하고, AI에게 역할을 분담시켜서 **기획부터 구현까지 자동화하는 방법**을 배워요.

## [참고] 오늘 나올 말 5개 {#terms}

앞으로 나올 말 중 설명 없이 지나가기 쉬운 것만 미리 짚어둘게요. **외우지 않으셔도 돼요** — 나중에 그 말이 나왔을 때 여기로 돌아오시면 됩니다.

| 말 | 뜻 |
|---|---|
| **토큰** | AI가 글을 읽고 쓸 때 세는 **분량 단위** |
| **컨텍스트** | 지금 대화에서 AI가 **기억하는 내용 전체** |
| **파이프라인** | 일이 **거쳐 가는 순서** (조사 → 해석 → 검수 → 저장) |
| **결정론적** | **같은 걸 넣으면 항상 같은 게 나오는** 일 (예: 파일 이름 바꾸기) |
| **커스텀 스킬** | 자주 하는 **작업 절차를 파일로 묶어둔 것** |

조금 더 풀어둘게요. **지금 안 읽으셔도 됩니다.**

**토큰** — 길게 주고받을수록 늘고, 그게 곧 **비용과 속도**예요. (한글은 한 글자가 대략 1~2토큰)

**컨텍스트** — 담을 수 있는 양이 정해져 있어서 **넘치면 앞부분을 잊습니다.** 2-1에서 조사원을 둘로 나누는 이유가 이거예요.

**파이프라인** — 이 워크북에서는 **커맨드로 부르는 세 가지**(비교 브리프·기회 카드·주간 리포트)를 가리키는 이름으로도 씁니다.

**결정론적** — 반대는 그때그때 답이 달라지는 일(조사·글쓰기)이에요.

**커스텀 스킬** — 오늘 직접 만들지는 않지만 2-4 끝에 한 번 나와요.
