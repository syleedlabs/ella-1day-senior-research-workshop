## [개념] 헷갈리기 쉬운 3가지 — 비유로 이해하기

이 3가지는 성격이 다릅니다. 혼동하기 쉬우니 **비유부터** 잡고 볼게요.

| 개념 | 비유 | 실제 역할/기능 |
|---|---|---|
| **에이전트** | 독립적인 역할과 업무를 가진 **정규 팀원** | 독립적인 역할과 프롬프트를 가진 **1급 실행 단위.** 각자의 전문 분야에서 **스스로 판단하며** 작업합니다 |
| **서브에이전트** | 팀원이 바쁠 때 잠깐 도움 받는 **임시 지원 인력** | 메인 대화의 **컨텍스트를 보호**하기 위해 임시로 생성되는 작업자. 작업이 끝나면 **사라집니다** |
| **오케스트레이션** | 팀장이 정규 팀원과 임시 인력을 배치하고 **조율**하는 것 | 여러 에이전트/서브에이전트의 **작업 순서, 역할 분담, 결과 종합**을 관리 |

## 시니어 리서치 에이전트 구조

나리님이 커맨드로 부르시는 건 **파이프라인**이에요. 셋 있고, 1-4에서 하나씩 다 돌려보셨습니다.

| 파이프라인 | 커맨드 | 전문 |
|---|---|---|
| **비교 브리프 파이프라인** | `/senior-compare-kr-global` | 주제 하나를 국내·해외로 파고들어 시차를 읽는다 |
| **기회 카드 파이프라인** | `/senior-biz-idea` | 조사 결과를 사업 기회 언어로 번역한다 |
| **주간 리포트 파이프라인** | `/senior-weekly-news` | 지난 한 주 흐름을 훑어 리포트로 묶는다 |

::: tip Part 2에서는 이 중 하나만 따라갑니다
개념마다 다른 걸 예로 들면 머리가 복잡해지거든요. **비교 브리프 파이프라인**으로 갑니다 — 셋 중 구조가 가장 풍부해서 설명거리가 많아요.

나머지 둘은 [부록 E](/appendix#other-agents)에 정리해뒀어요. 여기서 배운 게 **그대로 적용**됩니다.
:::

### 비교 브리프 파이프라인은 이렇게 생겼어요

커맨드 한 줄 뒤에 실제로는 **파일 네 개**가 물려 있습니다.

```
/senior-compare-kr-global              ← 나리님이 치는 슬래시 커맨드
  │
  ├─ .claude/agents/senior-compare-kr-global.md
  │     └ 명세 — 어떤 순서로, 어떤 형식으로 쓸지 (메인 대화가 읽음)
  │
  ├─ senior-research-kr        ┐
  ├─ senior-research-global    ├─ 일할 때만 잠깐 생겼다 사라지는
  └─ senior-source-check       ┘   서브에이전트 셋
```

**커맨드는 진입점일 뿐이고, 실제로 일을 나눠 하는 건 아래 셋**이에요.

::: tip 커맨드 이름이 두 개로 보이시죠
`/1-4-senior-compare-kr-global`(실습용)과 `/senior-compare-kr-global`(운영용)은 **하는 일이 같습니다.** 실습용은 앞에 챕터 번호만 붙었고, 워크숍 진행 안내가 조금 더 들어 있어요. 워크숍이 끝나면 **번호 없는 쪽**을 쓰시면 됩니다.
:::

### 안에서는 이렇게 흘렀어요

1-4에서 `/1-4-senior-compare-kr-global` 한 줄을 쳤을 때예요.

| 순서 | 누가 | 작업 | 세부 내용 |
|---|---|---|---|
| **1** | 메인 대화 | 주제 접수·조사 계획 | 무엇을 어디서 찾을지 정함 |
| **2** | **국내 조사원 + 해외 조사원**<br>*(서브에이전트 · 동시에)* | 자료 조사 | 각자 자기 몫만 읽고 **요약만** 돌려줌 |
| **3** | 메인 대화 | 시차 계산 → 브리프 | 요약 둘을 받아 해석 렌즈로 브리프를 씀 |
| **4** | **검수자**<br>*(서브에이전트)* | 출처·수치 품질 체크 | 📎 출처 유무, 원문 대조, 국내·해외 혼동 확인 |
| **5** | — | 저장 | `output/`에 날짜별 파일로 |

**2번에서 국내와 해외가 동시에 조사됐다**는 게 포인트예요. 순서대로 했으면 두 배 걸렸을 텐데, 나란히 진행돼서 한 번에 양쪽 결과가 나왔습니다.

## 1) 에이전트 (Agent) — 독립적인 1급 실행 단위

에이전트는 **AI + 도구 + 판단력**의 조합입니다. 세 가지가 다 있어야 에이전트예요.

- **AI** — 언어를 이해하고 답을 생성하는 두뇌
- **도구** — 웹을 검색하고, 파일을 읽고 쓰는 손발
- **판단력** — *"이 수치는 출처가 애매하니 미확인으로 빼자"* 같은 **스스로의 결정**

그냥 질문에 답만 하는 챗봇과 다른 지점이 바로 **판단력**이에요.

**나리님이 오늘 손에 넣은 시니어 리서치 에이전트가 바로 이겁니다.** 커맨드로 부르면 움직이고, 결과를 낸 뒤에도 *"더 깊게"*라고 하면 이어서 일해요.

::: tip 그럼 파이프라인은 뭔가요
**에이전트가 일을 처리하는 방식**이에요. 셋 중 어느 걸 부르든 움직이는 건 같은 에이전트고, **어떤 순서로 무엇을 할지가 다를 뿐**입니다.
:::

## 2) 서브에이전트 (Sub-Agent) — 임시 작업자

**비교 브리프 파이프라인 하나를 따라가 보면** 바로 이해돼요.

나리님이 *"시니어 주거"*를 주셨다고 해봅시다. 국내와 일본을 다 봐야 하는데, 통계 자료와 백서를 열면 **수십 페이지**예요. 이걸 혼자 다 읽으면 어떻게 될까요?

```
❌ 메인 대화가 혼자 다 읽으면

  국내 통계 30페이지 읽고 → 일본 백서 40페이지 읽고 → 해석하려니
  앞에서 본 국내 숫자가 가물가물… 일본 수치를 국내 걸로 착각
```

그래서 메인 대화는 **조수를 둘 부릅니다.**

```
⭕ 임시 작업자에게 나눠 맡기면

  메인 대화 ─┬─▶ 임시 작업자 A : 국내 자료만 읽고 → 요약 5줄
               └─▶ 임시 작업자 B : 일본 자료만 읽고 → 요약 5줄
                          (동시에 진행)
                             ↓
  메인 대화 ◀─── 요약 10줄만 받아서 해석
```

**메인 대화가 실제로 본 건 요약 10줄뿐**이에요. 70페이지는 임시 작업자들이 각자 자기 자리에서 읽고 소화했고, 그들은 요약을 넘긴 뒤 **사라졌습니다.**

이 임시 작업자가 **서브에이전트**예요. 세 가지 특징이 있습니다.

- **임시성** — 그 작업만 하고 **사라집니다.** 상주하지 않아요.
- **[컨텍스트](/part1/1-1-intro#terms) 보호** — 위 그림이 그대로 이 이야기예요. 70페이지가 메인 대화의 머릿속으로 쏟아지지 않습니다.
- **객관성** — 본체와 분리돼 있어 제3자의 눈으로 볼 수 있어요.

::: tip 그래서 얻는 게 두 가지예요
**속도** — 국내를 다 읽고 일본을 읽으면 두 배 걸립니다. 동시에 보내면 오래 걸리는 쪽만큼만 기다리면 돼요.

**정확도** — 국내 통계와 일본 백서를 한 머리에 다 넣으면 **숫자가 섞입니다.** 따로 읽고 요약만 가져오면 이 사고가 줄어요. 1-4에서 받으신 브리프에 국내·해외 숫자가 안 섞여 있던 이유가 이겁니다.
:::

::: tip 검수도 임시 작업자에게 맡긴 이유
흐름 표 4번의 검수도 같은 방식이에요. 그런데 여기선 **다른 이유**로 분리했습니다.

브리프를 **만든 쪽이 자기 걸 검사하면 후해지거든요.** 임시 작업자는 그 브리프가 어떻게 만들어졌는지 **모른 채** 결과물만 받습니다. 그래서 애착 없이 볼 수 있어요.

왜 이게 중요한지는 [2-3 하네스](/part2/2-3-harness)에서 자세히 다룹니다.
:::

## 3) 오케스트레이션 (Orchestration) — 전체 조율

일할 주체가 여럿이거나 같은 작업을 여러 번 굴려야 할 때, **순서·역할 분담·결과 종합**을 관리하는 게 오케스트레이션이에요. 앞서 본 **비교 브리프 파이프라인의 5단계 흐름 표** 전체가 오케스트레이션입니다.

### 오케스트레이션 패턴 5가지

| 패턴 | 설명 | 시니어 리서치라면 |
|---|---|---|
| **Fan Out** | 같은 작업을 여러 갈래에 동시 적용 | "시니어 주거"를 임대·분양·요양·코리빙으로 나눠 동시 조사 |
| **Specialized Roles** | 다른 역할의 작업자가 각자 전문 분석 | 조사·해석·검증을 각각 다른 담당에게 |
| **Parallel Research** | 여러 대상을 동시에 조사 | **← 1-4에서 이미 쓴 것.** 국내·해외 동시 조사가 이 패턴 |
| **Batch Generation** | 비슷한 결과물을 대량 생성 | 시니어 주제 10개를 한꺼번에 브리프로 |
| **Validation Pipeline** | 생성 → 검증을 파이프라인으로 연결 | 브리프 생성 → 검수 → 통과분만 저장 |

::: tip 이미 두 개를 쓰고 계셨어요
1-4에서 아무 설정도 안 하셨지만, 에이전트는 이미 **Parallel Research**(국내·해외 동시 조사)와 **Validation Pipeline**(생성 후 검수)을 돌리고 있었습니다.

패턴을 외워서 쓰는 게 아니라, **필요한 일을 시키면 자연스럽게 그 모양이 되는** 거예요. 나머지 세 패턴은 **확장의 지도**로 알아두시면 됩니다.
:::

::: tip [체크포인트] 여기까지 잡으셨다면
```
시니어 리서치 에이전트          ← 나리님이 오늘 손에 넣은 것
 └ 파이프라인 셋               ← 커맨드로 부르는 세 가지 일하는 방식
    └ 서브에이전트 셋           ← 그때그때 생겼다 사라지는 임시 작업자
```

- **에이전트** = 독립적인 1급 실행 단위 (= 나리님의 **시니어 리서치 에이전트**)
- **파이프라인** = 에이전트가 일을 처리하는 방식 (= 비교 브리프 · 기회 카드 · 주간 리포트)
- **서브에이전트** = 컨텍스트 보호를 위해 **임시로 생성되는 작업자** (= 국내 조사원 · 해외 조사원 · 검수자)
- **오케스트레이션** = 순서·역할 분담·결과 종합의 관리 (5패턴 중 **둘은 이미 쓰고 계셨어요**)

5패턴을 다 외우실 필요는 없어요 — 위 **3층 그림**만 머리에 남으면 충분합니다.
:::
