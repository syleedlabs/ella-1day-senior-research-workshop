## [개념] 헷갈리기 쉬운 3가지 — 비유로 이해하기

이 3가지는 성격이 다릅니다. 혼동하기 쉬우니 **비유부터** 잡고 볼게요.

| 개념 | 비유 | 실제 역할/기능 |
|---|---|---|
| **에이전트** | 독립적인 역할과 업무를 가진 **정규 팀원** | 독립적인 역할과 프롬프트를 가진 **1급 실행 단위.** 각자의 전문 분야에서 **스스로 판단하며** 작업합니다 |
| **서브에이전트** | 팀원이 바쁠 때 잠깐 도움 받는 **임시 지원 인력** | **다른 에이전트가 불러서 쓰는** 에이전트. 부름받은 그 순간의 이름이며, 메인 대화의 **컨텍스트를 보호**하려고 따로 띄운다. 일이 끝나면 결과만 남기고 **사라집니다** |
| **오케스트레이션** | 팀장이 정규 팀원과 임시 인력을 배치하고 **조율**하는 것 | 여러 에이전트/서브에이전트의 **작업 순서, 역할 분담, 결과 종합**을 관리 |

나리님이 커맨드로 부르시는 건 **파이프라인**이에요. 셋 있고, 1-4에서 하나씩 다 돌려보셨습니다.

| **주간 리포트 파이프라인** | `/senior-weekly-news` | 지난 한 주 흐름을 훑어 리포트로 묶는다 |

### 비교 브리프 파이프라인은 이렇게 생겼어요

커맨드 한 줄 뒤에 실제로는 **에이전트 네 개**가 물려 있습니다.

```
/senior-compare-kr-global                        ← 나리님이 치는 슬래시 커맨드
  │
  ├─ .claude/agents/senior-compare-kr-global     메인 대화가 이 파일을 읽고 전체를 진행
  │     조사원 둘을 부르고, 받아온 요약을 시차 렌즈로 해석해 브리프를 씀
  │
  ├─ .claude/agents/senior-research-kr           국내 자료만 조사한다
  │     통계청·보건복지부 등에서 찾아 요약만 돌려줌 · 해석은 안 함
  │
  ├─ .claude/agents/senior-research-global       일본·미국 자료만 조사한다
  │     지표 도달 연도까지 찾아옴 · 시차 계산은 안 함
  │
  └─ .claude/agents/senior-source-check          완성된 브리프를 검사한다
        📎 출처·수치·국내해외 혼동·미확인 라벨 · 고치지 않고 지적만 함
```

**아래 셋이 "해석은 안 함 · 계산은 안 함 · 고치지 않음"으로 좁혀져 있는 게 포인트**예요. 각자 자기 몫만 하고 넘기니까 서로 섞이지 않습니다.

### 안에서는 이렇게 흘렀어요

1-4에서 `/1-4-senior-compare-kr-global` 한 줄을 쳤을 때예요.

| 순서 | 작업 | 세부 내용 |
|---|---|---|
| **1** | 주제 접수·조사 계획 | 무엇을 어디서 찾을지 정함 |
| **2** | 자료 조사 | 국내·해외를 나눠 각자 자기 몫만 읽고 요약만 돌려줌 *(**서브에이전트로 분리**해 동시 진행)* |
| **3** | 시차 계산 → 브리프 작성 | 요약 둘을 받아 해석 렌즈로 씀 |
| **4** | 출처·수치 검수 | 📎 출처 유무, 원문 대조, 국내·해외 혼동 확인 *(**서브에이전트로 분리**)* |
| **5** | 저장 | `output/`에 날짜별 파일로 |

**2번과 4번만 밖으로 나갔다 오고, 나머지는 나리님과 대화하는 그 자리에서** 진행됩니다.

이 안에서 **에이전트 · 서브에이전트 · 오케스트레이션**이 각각 어떤 역할을 하는지 하나씩 살펴볼게요.

## 1) 에이전트 (Agent) — 독립적인 1급 실행 단위

위 표의 **1·3·5번** — 계획을 세우고, 해석해 브리프를 쓰고, 저장하는 그 자리가 에이전트예요. 나리님이 *"시니어 주거 조사해줘"*라고 하면 스스로 어디를 찾을지 정하고, 조사원을 부르고, 받아온 요약을 해석합니다. **사람이 매 단계를 지시하지 않아도 다음 할 일을 스스로 판단합니다.**

> **핵심**: 에이전트는 **독립적인 역할과 프롬프트**를 가집니다.

- 자기만의 전문 영역이 있습니다 (우리 경우 **시니어 시장 리서치**)
- 스스로 판단해서 작업을 수행합니다 — *"이 수치는 출처가 애매하니 미확인으로 빼자"*
- 에이전트 = **AI + 도구(Tools) + 판단력(Reasoning)**

그냥 질문에 답만 하는 챗봇과 다른 지점이 바로 **판단력**이에요. 나리님이 오늘 손에 넣은 **시니어 리서치 에이전트**가 바로 이겁니다.

## 2) 서브에이전트 (Sub-Agent) — 임시 작업자

위 표 **2번과 4번**의 세부 내용에 *"서브에이전트로 분리"*라고 적혀 있습니다. 서브에이전트는 **다른 에이전트가 불러서 쓰는 에이전트**예요 — 부름을 받은 그 순간, 그 자리에서만 서브에이전트입니다.

> **핵심**: 서브에이전트는 **임시**입니다. 메인 대화의 [컨텍스트](/part1/1-1-intro#terms)를 보호하려고 따로 띄웁니다.

- 메인 대화가 너무 길어지는 것을 방지합니다
- 무거운 작업을 분리해서 처리합니다
- 작업이 끝나면 **결과만 남기고 사라집니다**

비교 브리프를 만들려면 국내 통계와 일본 백서를 다 봐야 하는데, 열면 **수십 페이지**예요. 메인 대화가 이걸 혼자 다 읽으면 앞에서 본 국내 숫자가 가물가물해지고, 일본 수치를 국내 걸로 착각하게 됩니다. 그래서 메인 대화는 **조사원 둘을 임시로 생성해서** 국내와 일본을 나눠 맡기고, **요약만 받아서** 해석에 집중합니다.

```
  메인 대화 ─┬─▶ 국내 조사원 : 국내 자료만 읽고 → 요약 5줄
             └─▶ 해외 조사원 : 일본 자료만 읽고 → 요약 5줄
                        (동시에 진행)
                           ↓
  메인 대화 ◀─── 요약 10줄만 받아서 해석
```

**메인 대화가 실제로 본 건 요약 10줄뿐**이에요. 70페이지는 조사원들이 각자 읽고 소화했고, 그들은 요약을 넘긴 뒤 사라졌습니다.

::: tip 그래서 얻는 게 두 가지예요
**속도** — 국내를 다 읽고 일본을 읽으면 두 배 걸립니다. 동시에 보내면 오래 걸리는 쪽만큼만 기다리면 돼요.

**정확도** — 국내 통계와 일본 백서를 한 머리에 다 넣으면 **숫자가 섞입니다.** 따로 읽고 요약만 가져오면 이 사고가 줄어요. 1-4에서 받으신 브리프에 국내·해외 숫자가 안 섞여 있던 이유가 이겁니다.
:::

::: tip 검수도 임시 작업자에게 맡긴 이유
표 4번의 검수도 같은 방식인데, 여기선 **다른 이유**로 분리했습니다.

브리프를 **만든 쪽이 자기 걸 검사하면 후해지거든요.** 임시 작업자는 그 브리프가 어떻게 만들어졌는지 **모른 채** 결과물만 받습니다. 그래서 애착 없이 볼 수 있어요.

왜 이게 중요한지는 [2-4 하네스](/part2/2-4-harness)에서 자세히 다룹니다.
:::

## 3) 오케스트레이션 (Orchestration) — 전체 조율

**위 표 전체가 오케스트레이션입니다.** 계획 → 조사(둘로 나눠 동시) → 해석 → 검수 → 저장 순서로, **누가 언제 무엇을 할지** 전체 흐름을 설계하고 조율하는 것이에요.

### 오케스트레이션 패턴 5가지

| 패턴 | 설명 | 시니어 리서치라면 |
|---|---|---|
| **Fan Out** | 같은 작업을 여러 갈래에 동시 적용 | "시니어 주거"를 임대·분양·요양·코리빙으로 나눠 동시 조사 |
| **Specialized Roles** | 다른 역할의 작업자가 각자 전문 분석 | 조사·해석·검증을 각각 다른 담당에게 |
| **Parallel Research** | 여러 대상을 동시에 조사 | **← 1-4에서 이미 쓴 것.** 국내·해외 동시 조사가 이 패턴 |
| **Batch Generation** | 비슷한 결과물을 대량 생성 | 시니어 주제 10개를 한꺼번에 브리프로 |
| **Validation Pipeline** | 생성 → 검증을 파이프라인으로 연결 | 브리프 생성 → 검수 → 통과분만 저장 |
