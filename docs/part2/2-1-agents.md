## [개념] 헷갈리기 쉬운 3가지 — 비유로 이해하기

세 단어가 비슷해 보이지만 **층위가 다릅니다.** 팀으로 비유하면 한 번에 잡혀요.

| 개념 | 비유 | 실제 역할 |
|---|---|---|
| **에이전트** | 독립적인 역할과 업무를 가진 **정규 팀원** | 독립적 프롬프트와 판단력을 갖춘 **1급 실행 단위** |
| **서브에이전트** | 팀원이 바쁠 때 잠깐 도움받는 **임시 지원 인력** | 메인 대화의 **컨텍스트를 보호**하기 위해 임시로 생성되는 작업자 |
| **오케스트레이션** | 팀장이 정규 팀원과 임시 인력을 **배치·조율** | 여러 에이전트의 **순서·역할 분담·결과 종합** 관리 |

## 시니어 리서치 봇의 에이전트 구조

1-4에서 `/1-4-senior-compare-kr-global` 한 줄을 쳤을 때, 안에서는 이렇게 흘렀어요.

::: tip 커맨드 이름이 두 개로 보이시죠
`/1-4-senior-compare-kr-global`(실습용)과 `/senior-compare-kr-global`(운영용)은 **하는 일이 같습니다.** 실습용은 앞에 챕터 번호만 붙었고, 워크숍 진행 안내가 조금 더 들어 있어요. 워크숍이 끝나면 **번호 없는 쪽**을 쓰시면 됩니다.
:::

| 순서 | 에이전트 | 작업 | 세부 내용 |
|---|---|---|---|
| **1** | **메인 대화** | 주제 접수·조사 계획 | 무엇을 어디서 찾을지 정함 |
| **2** | **비교 브리프** | 조사 → 시차 계산 → 브리프 | 국내·해외 자료 수집 *(국내/해외를 **서브에이전트로 분리**해 동시 조사)*, 렌즈로 해석 |
| **3** | **검수** | 출처·수치 품질 체크 | 📎 출처 유무, 원문 대조, 국내·해외 혼동 확인 *(**서브에이전트로 분리**)* |
| **4** | — | 저장 | `output/`에 날짜별 파일로 |

**2번에서 국내와 해외가 동시에 조사됐다**는 게 포인트예요. 순서대로 했으면 두 배 걸렸을 텐데, 나란히 진행돼서 한 번에 양쪽 결과가 나왔습니다.

## 1) 에이전트 (Agent) — 독립적인 1급 실행 단위

에이전트는 **AI + 도구 + 판단력**의 조합입니다. 세 가지가 다 있어야 에이전트예요.

- **AI** — 언어를 이해하고 답을 생성하는 두뇌
- **도구** — 웹을 검색하고, 파일을 읽고 쓰는 손발
- **판단력** — *"이 수치는 출처가 애매하니 미확인으로 빼자"* 같은 **스스로의 결정**

그냥 질문에 답만 하는 챗봇과 다른 지점이 바로 **판단력**이에요.

위 표의 **비교 브리프**가 에이전트입니다. 나리님이 커맨드로 부르면 움직이고, 결과를 낸 뒤에도 *"더 깊게"*라고 하면 이어서 일해요.

::: tip 우리 봇은 에이전트가 셋이에요
| 에이전트 | 커맨드 | 전문 |
|---|---|---|
| **비교 브리프** | `/senior-compare-kr-global` | 주제 하나를 국내·해외로 파고들어 시차를 읽는다 |
| **기회 카드** | `/senior-biz-idea` | 조사 결과를 사업 기회 언어로 번역한다 |
| **주간 리포트** | `/senior-weekly-news` | 지난 한 주 흐름을 훑어 리포트로 묶는다 |

셋은 **같은 규율을 공유**해요 — 일본을 시차 렌즈로 쓰고, 숫자엔 📎 출처를 대고, 확인 못 한 건 ⚠️ 미확인이라 말한다. 하는 일만 다를 뿐이라, 어느 걸 부르든 결과물의 **성격이 일관**됩니다.
:::

## 2) 서브에이전트 (Sub-Agent) — 임시 작업자

**비교 브리프 에이전트 한 명을 따라가 보면** 바로 이해돼요.

나리님이 *"시니어 주거"*를 주셨다고 해봅시다. 비교 브리프는 국내와 일본을 다 봐야 하는데, 통계 자료와 백서를 열면 **수십 페이지**예요. 이걸 혼자 다 읽으면 어떻게 될까요?

```
❌ 비교 브리프가 혼자 다 읽으면

  국내 통계 30페이지 읽고 → 일본 백서 40페이지 읽고 → 해석하려니
  앞에서 본 국내 숫자가 가물가물… 일본 수치를 국내 걸로 착각
```

그래서 비교 브리프는 **조수를 둘 부릅니다.**

```
⭕ 임시 작업자에게 나눠 맡기면

  비교 브리프 ─┬─▶ 임시 작업자 A : 국내 자료만 읽고 → 요약 5줄
               └─▶ 임시 작업자 B : 일본 자료만 읽고 → 요약 5줄
                          (동시에 진행)
                             ↓
  비교 브리프 ◀─── 요약 10줄만 받아서 해석
```

**비교 브리프가 실제로 본 건 요약 10줄뿐**이에요. 70페이지는 임시 작업자들이 각자 자기 자리에서 읽고 소화했고, 그들은 요약을 넘긴 뒤 **사라졌습니다.**

이 임시 작업자가 **서브에이전트**예요. 세 가지 특징이 있습니다.

- **임시성** — 그 작업만 하고 **사라집니다.** 상주하지 않아요.
- **[컨텍스트](/part1/1-1-intro#terms) 보호** — 위 그림이 그대로 이 이야기예요. 70페이지가 비교 브리프의 머릿속으로 쏟아지지 않습니다.
- **객관성** — 본체와 분리돼 있어 제3자의 눈으로 볼 수 있어요.

::: tip 그래서 얻는 게 두 가지예요
**속도** — 국내를 다 읽고 일본을 읽으면 두 배 걸립니다. 동시에 보내면 오래 걸리는 쪽만큼만 기다리면 돼요.

**정확도** — 국내 통계와 일본 백서를 한 머리에 다 넣으면 **숫자가 섞입니다.** 따로 읽고 요약만 가져오면 이 사고가 줄어요. 1-4에서 받으신 브리프에 국내·해외 숫자가 안 섞여 있던 이유가 이겁니다.
:::

::: tip 검수도 임시 작업자에게 맡긴 이유
표 3번의 검수도 같은 방식이에요. 그런데 여기선 **다른 이유**로 분리했습니다.

브리프를 **만든 쪽이 자기 걸 검사하면 후해지거든요.** 임시 작업자는 그 브리프가 어떻게 만들어졌는지 **모른 채** 결과물만 받습니다. 그래서 애착 없이 볼 수 있어요.

왜 이게 중요한지는 [2-3 하네스](/part2/2-3-harness)에서 자세히 다룹니다.
:::

## 3) 오케스트레이션 (Orchestration) — 전체 조율

에이전트가 여럿이거나 같은 작업을 여러 번 굴려야 할 때, **순서·역할 분담·결과 종합**을 관리하는 게 오케스트레이션이에요. 위 표 전체가 오케스트레이션입니다.

### 오케스트레이션 패턴 5가지

| 패턴 | 설명 | 시니어 리서치라면 |
|---|---|---|
| **Fan Out** | 같은 작업을 여러 갈래에 동시 적용 | "시니어 주거"를 임대·분양·요양·코리빙으로 나눠 동시 조사 |
| **Specialized Roles** | 다른 역할의 에이전트가 각자 전문 분석 | 조사·해석·검증을 각각 다른 담당에게 |
| **Parallel Research** | 여러 대상을 동시에 조사 | **← 1-4에서 이미 쓴 것.** 국내·해외 동시 조사가 이 패턴 |
| **Batch Generation** | 비슷한 결과물을 대량 생성 | 시니어 주제 10개를 한꺼번에 브리프로 |
| **Validation Pipeline** | 생성 → 검증을 파이프라인으로 연결 | 브리프 생성 → 검수 → 통과분만 저장 |

::: tip 이미 두 개를 쓰고 계셨어요
1-4에서 아무 설정도 안 하셨지만, 봇은 이미 **Parallel Research**(국내·해외 동시 조사)와 **Validation Pipeline**(생성 후 검수)을 돌리고 있었습니다.

패턴을 외워서 쓰는 게 아니라, **필요한 일을 시키면 자연스럽게 그 모양이 되는** 거예요. 나머지 세 패턴은 **확장의 지도**로 알아두시면 됩니다.
:::

::: tip [체크포인트] 여기까지 잡으셨다면
- **에이전트** = 독립적인 1급 실행 단위 (= 우리 봇 **셋**: 비교 브리프·기회 카드·주간 리포트)
- **서브에이전트** = 컨텍스트 보호를 위해 **임시로 생성되는 작업자** (= 국내·해외 조사, 검수)
- **오케스트레이션** = 순서·역할 분담·결과 종합의 관리 (5패턴 중 **둘은 이미 쓰고 계셨어요**)

5패턴을 다 외우실 필요는 없어요 — "**에이전트 셋 + 필요할 때 임시 작업자**"만 머리에 남으면 충분합니다.
:::
