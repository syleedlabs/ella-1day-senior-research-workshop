# 2-1. 에이전트

::: tip Step 5 / 8 · Part 2
이 챕터에서 — **에이전트·서브에이전트·오케스트레이션이 각각 무엇인지**, 그리고 방금 1-4에서 돌린 리서치 봇이 이 그림 안에서 어디에 서 있는지 함께 정리해봅시다.
:::

::: tip 방금 본 것들이 다 '에이전트'예요
1-3에서 본 강사의 딜 아카이브 — **리서치하는 부분, 제안하는 부분, 콘텐츠 만드는 부분** — 그리고 1-4에서 나리님이 직접 돌린 **시니어 리서치 봇**. 이게 전부 이 챕터에서 말하는 "에이전트"예요. 새 개념을 배우는 게 아니라, **이미 해본 것에 이름표**를 다는 시간이에요.
:::

## [개념] 팀으로 비유하면 한 번에 잡혀요

에이전트라는 말이 처음엔 추상적으로 들릴 수 있어요. 그래서 **팀**으로 비유해봅니다.

| 개념 | 팀 비유 | **구분 기준 — 이것만 기억하시면 돼요** |
|---|---|---|
| **에이전트** | 정규 팀원 | **나리님이 직접 부르고, 나리님과 대화가 이어집니다.** 결과를 보고 "더 깊게"라고 하면 이어서 해줘요 |
| **서브에이전트** | 임시 지원 인력 | **봇이 알아서 부릅니다.** 나리님과 대화하지 않고, 자기 일만 해서 결과만 넘기고 사라져요 |
| **오케스트레이션** | 배치·조율하는 팀장 | 누구에게 무엇을 언제 맡길지 정하는 **방식** |

가르는 선은 **"누가 부르느냐, 나와 말을 섞느냐"**예요.

- 나리님이 `/senior-compare-kr-global`을 치면 → **에이전트**를 부른 겁니다. 대화가 이어져요.
- 그 에이전트가 조사원 둘을 불러 일을 시키면 → 그 둘이 **서브에이전트**예요. 나리님은 그들과 말을 섞지 않고, 결과만 브리프 안에서 봅니다.

## [개념] 아까 그 브리프는 이렇게 나왔어요

말로 설명하는 대신, **1-4에서 나리님이 실제로 돌린 그 실행**을 해부해볼게요. `/1-4-senior-compare-kr-global` 한 줄을 쳤을 때 안에서 벌어진 일입니다.

::: tip 커맨드 이름이 두 개로 보이시죠
`/1-4-senior-compare-kr-global`(실습용)과 `/senior-compare-kr-global`(운영용)은 **하는 일이 같습니다.** 실습용은 앞에 챕터 번호만 붙였고, 워크숍 진행 안내가 조금 더 들어 있어요.

워크숍이 끝나면 **번호 없는 쪽**을 쓰시면 됩니다. 뒷부분 이름이 같아서 손에 익은 그대로예요.
:::

| 순서 | 누가 | 무슨 일을 했나 |
|---|---|---|
| ① | **메인 대화** | 나리님이 준 주제를 받아, 뭘 어떻게 조사할지 계획 |
| ② | **임시 조사원 A** (`senior-research-kr`) | **국내** 자료를 웹에서 조사 ┐ |
| ③ | **임시 조사원 B** (`senior-research-global`) | **해외(일본·미국)** 자료 + 지표 도달 연도 ┘ ← ②와 **동시에** |
| ④ | **메인 대화** | 둘을 받아 시차를 계산하고 해석 → 브리프 작성 |
| ⑤ | **검수자** (`senior-source-check`) | 📎 출처가 다 붙었는지, 숫자가 원문과 맞는지 **처음 보는 눈으로** 확인 |

::: tip 직접 확인해보실 수 있어요
`.claude/agents/` 폴더를 열어보시면 위 이름들이 파일로 있습니다. 그림으로만 설명하는 게 아니라 **실제로 그렇게 돌아가요.**

폴더에 파일이 6개인데, **나리님이 커맨드로 부르는 건 3개**(비교 브리프·기회 카드·주간 리포트)뿐이에요. 나머지 3개(조사원 둘 + 검수자)는 **봇이 알아서 부르는** 것들입니다.
:::

여기서 **②③이 동시에 돌았다**는 게 포인트예요. 국내 조사가 끝나길 기다렸다가 해외를 조사한 게 아니라, 둘이 나란히 진행됐습니다. 1~2분 만에 양쪽 결과가 다 나온 이유가 이거예요.

## [개념] 에이전트 — 독립적 역할을 가진 정규 팀원

에이전트는 **AI + 도구 + 판단력**의 조합입니다. 세 가지가 다 있어야 에이전트예요.

- **AI** — 언어를 이해하고 답을 생성하는 두뇌.
- **도구** — 웹을 검색하고, 파일을 읽고 쓰고, 커맨드를 실행하는 손발.
- **판단력** — "이 수치는 출처가 애매하니 미확인으로 빼자" 같은 **스스로의 결정**.

그냥 질문에 답만 하는 챗봇과 다른 지점이 바로 **판단력**이에요.

::: tip 우리 봇은 **세 명의 정규 팀원**이에요
시니어 리서치 봇은 하나가 아니라 **세 에이전트**로 나뉩니다 — 나리님이 **커맨드로 직접 부르고 대화가 이어지는** 팀원들이에요.

| 에이전트 | 커맨드 | 전문 |
|---|---|---|
| **비교 브리프** | `/senior-compare-kr-global` | 주제 하나를 국내·해외로 파고들어 시차를 읽는다 |
| **기회 카드** | `/senior-biz-idea` | 조사 결과를 사업 기회 언어로 번역한다 |
| **주간 리포트** | `/senior-weekly-news` | 지난 한 주 흐름을 훑어 리포트로 묶는다 |

셋은 **같은 규율을 공유**해요 — 일본을 시차 렌즈로 쓰고, 숫자엔 📎 출처를 대고, 확인 못 한 건 ⚠️ 미확인이라 말한다. 하는 일만 다를 뿐이에요. 그래서 어느 걸 부르든 나오는 결과물의 **성격이 일관**됩니다.
:::

## [개념] 서브에이전트 — 잠깐 부르는 임시 지원 인력

위 표의 **② 임시 조사원 A·B**가 바로 서브에이전트예요. 세 가지 특징이 있습니다.

- **임시성** — 필요할 때 생겼다가, 조사가 끝나면 사라집니다. 상주하지 않아요.
- **맥락([컨텍스트](/part1/1-1-intro#terms)) 보호** — 국내 자료를 뒤지며 읽은 수십 페이지가 메인 대화로 쏟아지지 않습니다. 조사원은 자기 공간에서 다 읽고, **정리된 결과만** 넘겨요.
- **객관성** — 본체와 분리돼 있어서, 본체가 만든 결과를 제3자의 눈으로 볼 수 있습니다.

::: tip 잠깐 왔다 사라지는데, 이름이 왜 있죠?
당연히 드는 의문이에요. `.claude/agents/` 폴더를 열면 `senior-research-kr.md` 같은 **이름 붙은 파일**이 버젓이 있으니까요.

**이름이 붙은 건 '사람'이 아니라 '역할'입니다.**

그 파일은 사람이 아니라 **직무기술서**예요 — *"국내 자료만 조사할 것. 출처를 붙일 것. 해석은 하지 말 것."* 이 문서는 폴더에 **계속 남아 있습니다.**

브리프를 만들 때마다 봇은 이 기술서를 보고 조사원을 **새로 한 명 부릅니다.** 그 조사원은 자기 일만 하고 결과를 넘긴 뒤 사라져요. 다음에 또 부르면 **앞 일을 기억하지 못하는 새 조사원**이 옵니다.

> 정리하면 — **역할(파일)은 상주하고, 그 역할로 불려온 일꾼(실행)이 임시**입니다.

기억을 못 하는 게 단점 같지만 **오히려 장점**이에요. 검수자가 매번 "처음 보는 눈"으로 볼 수 있는 이유가 이겁니다. 앞에서 무슨 일이 있었는지 모르니까 봐주고 말고 할 게 없죠.
:::

::: tip 왜 국내/해외를 나눠 보냈을까요
두 가지 이유예요.

**첫째, 속도.** 순서대로 하면 두 배 걸립니다. 동시에 보내면 오래 걸리는 쪽만큼만 기다리면 돼요.

**둘째, 맥락 보호.** 국내 통계 자료와 일본 백서를 **한 대화에 다 쏟아부으면** 봇이 뒤죽박죽이 됩니다. 앞에서 읽은 걸 잊거나, 국내 수치를 일본 것으로 착각하기도 해요. 따로 읽고 **요약본만 가져오게** 하면 이런 사고가 줄어듭니다.
:::

## [개념] 오케스트레이션 — 팀장의 배치·조율

에이전트가 여럿이거나 같은 작업을 여러 번 굴려야 할 때, **어떻게 나눠 붙일지**를 정하는 게 오케스트레이션이에요. 대표적인 5패턴입니다.

| 패턴 | 한 줄 뜻 | 시니어 리서치라면 |
|---|---|---|
| **Fan Out (팬아웃)** | 한 작업을 여러 갈래로 펼쳐 동시에 처리 | "시니어 주거"를 임대·분양·요양·코리빙 갈래로 나눠 동시 조사 |
| **Specialized Roles (전문 역할 분담)** | 역할별 전담 에이전트로 나눔 | 조사는 조사원이, 해석은 브리프 에이전트가, 검증은 검수자가 |
| **Parallel Research (병렬 리서치)** | 여러 대상을 동시에 조사 | **← 우리가 1-4에서 이미 쓴 것.** 국내·해외를 동시에 조사한 게 바로 이 패턴 |
| **Batch Generation (배치 생성)** | 같은 작업을 여러 입력에 일괄 적용 | 시니어 주제 10개를 한꺼번에 브리프로 |
| **Validation Pipeline (검증 파이프라인)** | 생성 → 검증을 파이프라인으로 연결 | 브리프 생성 → 검수자가 출처 확인 → 통과분만 저장 |

::: tip 이미 두 개를 쓰고 계셨어요
1-4에서 아무 설정도 안 하셨지만, 봇은 이미 **Parallel Research**(국내·해외 동시 조사)와 **Validation Pipeline**(출처 검수)을 돌리고 있었습니다. 패턴을 외워서 쓰는 게 아니라, **필요한 일을 시키면 자연스럽게 그 모양이 되는** 거예요.

나머지 세 패턴은 **확장의 지도**로 알아두시면 됩니다. 나중에 "주제 열 개를 한꺼번에" 같은 게 필요해질 때 이름표가 방향을 알려줘요.
:::

## [개념] 우리 봇을 이 그림에 얹어보면

정리하면 이렇게 서요.

- **에이전트** = 시니어 리서치 봇의 **세 정규 팀원** — 비교 브리프 · 기회 카드 · 주간 리포트. 같은 규율을 공유하며, 나리님이 커맨드로 직접 부르는 메인 팀원.
- **서브에이전트** = `senior-research-kr`(국내 조사원) · `senior-research-global`(해외 조사원) · `senior-source-check`(출처 검수자). 일이 끝나면 사라지는 임시 인력.
- **오케스트레이션** = 이들을 잇는 흐름. 지금은 `병렬 조사 → 해석 → 검수` 정도의 가벼운 파이프라인이고, 나머지 패턴은 확장용 지도.

::: tip [체크포인트] 여기까지 잡으셨다면
- 가르는 선은 **"누가 부르느냐, 나와 말을 섞느냐"**
- 에이전트 = **내가 직접 부르고 대화가 이어지는** 정규 팀원 (= 우리 봇 **셋**: 브리프·기회카드·주간리포트)
- 서브에이전트 = **봇이 알아서 부르고, 결과만 넘기고 사라지는** 임시 인력 (= 국내 조사원 · 해외 조사원 · **검수자**)
- **역할(파일)은 남고, 그 역할로 불려온 일꾼이 임시** — 그래서 매번 "처음 보는 눈"이 된다
- 오케스트레이션 = 여러 일꾼을 배치·조율하는 방식 (5패턴 중 **둘은 이미 쓰고 계셨어요**)

5패턴을 다 외우실 필요는 없어요 — "**정규 팀원 셋 + 임시 조사원들**"만 머리에 남으면 충분합니다.
:::
