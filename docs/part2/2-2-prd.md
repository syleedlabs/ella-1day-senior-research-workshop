# 2-2. PRD (제품 요구사항 문서)

::: tip Step 6 / 8
1-4에서 브리프가 **매번 같은 형태로** 나온 게 우연이었을까요? 아니에요. 에이전트 뒤에 **PRD**라는 지시서가 깔려 있었거든요.
:::

## [개념] PRD(Product Requirements Document)란?

AI에게 이렇게 말한다고 해봅시다.

> "시니어 시장 리서치 에이전트 하나 만들어줘."

만들긴 만듭니다. 그런데 나오는 건 **인터넷 평균치 챗봇**이에요. 출처도 없고, 국내·해외 비교도 없고, 모르는 걸 모른다고 하지도 않습니다. 이유는 하나 — **지시가 모호했기 때문**이에요.

AI는 마음을 읽지 못합니다. 머릿속 그림이 아무리 선명해도 **적어주지 않은 것은 만들어지지 않아요.**

> **PRD**는 AI 에이전트에게 주는 **상세 업무 지시서**예요. "무엇을 해야 하는지"를 정확하게 전달합니다.

담기는 건 여섯 가지입니다.

| 항목 | 역할 | 우리 에이전트의 예시 |
|---|---|---|
| **목적** | 이 시스템이 왜 필요한지 | "시니어 시장을 국내·해외 교차로 조사해 판단 재료를 만든다" |
| **목표 지표** | 성공을 어떻게 측정할지 | "모든 수치에 출처 표기 · 국내·해외 양쪽 최소 1개 소스" |
| **파이프라인 구성** | 누가 어떤 역할을 맡는지 | "비교 브리프 · 기회 카드 · 주간 리포트 + 임시 조사원·검수자" |
| **작업 흐름** | 작업이 어떤 순서로 흐르는지 | "주제 접수 → 국내·해외 동시 조사 → 시차 해석 → 검수 → 저장" |
| **입출력 정의** | 무엇을 넣고 무엇이 나오는지 | "시니어 주제 한 줄 → 국내·해외 비교 브리프 md" |
| **품질 기준** | 어떤 기준을 지켜야 하는지 | "📎 출처 필수, ⚠️ 미확인 라벨, 지어내기 금지" |

PRD의 가치는 **재현성**이에요. 1-4에서 나리님이 돌린 브리프가 매번 같은 형태로 나온 건 우연이 아니라, 이 명세가 미리 적혀 있었기 때문입니다.

## [개념] 그 명세가 어느 파일에 있나

[2-1](/part2/2-1-agents)에서 본 구조를 **파일 관점**으로 다시 보면 이렇습니다.

```
CLAUDE.md                              ← 셋이 공유하는 헌법 (품질 기준·비교 축)
  │
/senior-compare-kr-global              ← 나리님이 치는 슬래시 커맨드
  │
  ├─ .claude/agents/senior-compare-kr-global.md
  │     └ 이 파이프라인의 명세 — 절차와 출력 형식 (부름을 받고 전체를 진행)
  │
  ├─ senior-research-kr        ┐
  ├─ senior-research-global    ├─ 위가 부르는 에이전트 셋
  └─ senior-source-check       ┘   (부름받은 순간 = 서브에이전트)
```

**PRD는 위에서 두 층에 나뉘어 적혀 있어요** — 셋이 공통으로 지킬 것은 `CLAUDE.md`에, 이 파이프라인만의 절차·형식은 `agents/senior-compare-kr-global.md`에.

어느 쪽을 고쳐야 할지 헷갈리시면 **파일을 열지 마시고 클로드 코드에게 그냥 말씀하세요** — *"에이전트가 출처를 자꾸 빠뜨리는데 어디를 고치면 돼?"* 라고 물으면 알아서 찾아갑니다.

## [개념] 우리 에이전트의 PRD 살펴보기

1-4에서 나리님이 돌린 에이전트에 **실제로 적혀 있는** 내용이에요.

| 항목 | 내용 |
|---|---|
| **1. 개요** | **목적**: 인구구조 변화 속 시니어 시장을 국내·해외 교차로 조사<br>**핵심 가치**: 탭 스무 개 열고 반나절 → **몇 분** |
| **2. 전략 및 목표** | 읽는 사람: 시니어 시장 진입·확장을 검토하는 기획/사업 담당자<br>잘했다의 기준: 출처 100% 표기 · 국내·해외 양쪽 최소 1개 소스 · **시차 표현 포함** |
| **3. 파이프라인 구성** | **비교 브리프**(조사→해석) · **기회 카드**(사업 언어로 번역) · **주간 리포트**(한 주 훑기)<br>+ 임시 작업자: 국내 조사원 · 해외 조사원 · 검수자 |
| **4. 작업 흐름** | 주제 접수 → **국내·해외 동시 조사** → 시차 계산·해석 → 검수 → `output/` 저장 |
| **5. 품질 기준** | 📎 출처(매체+발행일) · ⚠️ 미확인 라벨 · 지어내기 금지 · 국내/해외 수치 혼동 금지 |

### 에이전트의 판단 기준도 PRD에 들어 있어요

에이전트가 **스스로 결정**하려면 기준이 필요합니다. 우리 에이전트엔 이런 게 박혀 있어요.

| 무엇을 | 어떻게 정해뒀나 |
|---|---|
| **비교 대상국** | **일본 고정**(시차 렌즈) + **미국 보조**(규모·자본). 임의로 안 바꿈 |
| **해석 렌즈** | 인구 피라미드 · 액티브/케어 시니어 구분 · 일본 선행 시차 |
| **소스 우선순위** | 공식 통계 > 정부 기관 > 업계 리포트 > 언론 기사 (기관 목록은 `CLAUDE.md`에) |
| **출력 형식** | 국내·해외 2단 → 💡 시사점 → 📎 출처 → ⚠️ 미확인 → 💬 다음 질문 |
| **안전 정책** | 투자·의료 판단은 단정하지 않고 전문가 확인 권유. 추정은 "추정"이라 명시 |

**품질 기준 칸이 이 PRD의 심장**입니다. 이게 없으면 에이전트는 그냥 말 잘하는 챗봇이에요.

## 클로드 코드에게 PRD를 요청하는 방법

PRD를 나리님이 직접 쓰실 필요는 없어요. **클로드 코드에게 만들어달라고 하면 됩니다.**

```
나는 [자동화하고 싶은 업무]를 하고 있어.
현재는 [현재 작업 방식]으로 진행하고 있는데,
이걸 자동화하기 위한 PRD를 작성해줘.
```

나리님 일로 채우면 이렇게 돼요.

```
나는 시니어 시장 신사업을 검토하는 일을 하고 있어.
현재는 통계청 자료 열고, 일본 사례 찾고, 뉴스 뒤지는 걸 매번 손으로 하는데,
이걸 자동화하기 위한 PRD를 작성해줘.
```

::: tip 더 좋게 만드는 한 줄
PRD를 요청하실 때 [부록의 **인터뷰 프롬프트**](/appendix#interview)를 앞에 붙이면 훨씬 정확해져요.

```
바로 만들지 말고, 제가 뭘 원하는지 이해될 때까지 저를 인터뷰해주세요.
```

클로드가 *"결과를 파일로 저장할까요?"*, *"어떤 소스를 신뢰하세요?"* 같은 걸 먼저 물어봅니다. 답하다 보면 **나리님 요구사항이 정리돼요.**
:::

::: tip 오늘은 안 하셔도 돼요
우리 에이전트의 PRD는 **이미 적용된 상태**입니다. 이 방법은 나중에 **다른 자동화를 만들고 싶어지실 때** 쓰세요.
:::


::: tip [체크포인트] 여기까지 잡으셨다면
- PRD = AI에게 주는 **상세 업무 지시서** (목적·목표지표·역할 분담·작업 흐름·입출력·품질 기준)
- **1-4에서 돌린 에이전트 뒤에 이 PRD가 있었다**는 걸 이해함
- **클로드 코드에게 PRD를 요청하는 방법**을 안다 (+ 인터뷰 프롬프트를 앞에 붙이면 더 정확)
- 그 명세가 **어느 파일에 나뉘어 사는지** 안다
:::
