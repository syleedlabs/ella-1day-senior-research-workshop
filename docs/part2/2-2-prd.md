# 2-2. PRD 설계도

::: tip Step 6 / 8 · Part 2
이 챕터에서 — 봇에게 "무엇을 어떻게 조사할지" 명확히 적어주는 **봇 PRD**가 왜 필요한지, 무엇을 담는지, 그리고 그 명세가 실제로 사는 파일인 **`CLAUDE.md`**를 어떻게 쓰는지까지 함께 잡습니다.
:::

## [개념] 모호한 지시 vs 명확한 명세

AI에게 이렇게 말한다고 해봅시다.

> "시니어 시장 리서치 봇 하나 만들어줘."

만들긴 만듭니다. 그런데 나오는 건 **인터넷 평균치 챗봇**이에요. 출처도 없고, 국내·해외 비교도 없고, 모르는 걸 모른다고 하지도 않습니다. 이유는 하나 — **지시가 모호했기 때문**이에요.

AI는 마음을 읽지 못합니다. 머릿속 그림이 아무리 선명해도, **적어주지 않은 것은 만들어지지 않아요.** 그래서 "만들어줘" 대신 **만들 것을 명확히 적은 지시서**를 먼저 씁니다. 이 지시서를 **PRD(Product Requirements Document, 제품 요구사항 문서)** 라고 불러요.

| | 모호한 지시 | 명확한 명세(PRD) |
|---|---|---|
| 결과 | 돌릴 때마다 다른 형태 | 언제 돌려도 같은 형식의 브리프 |
| 근거 | 알아서 (=아무 데나) | 신뢰 소스를 지정하고 📎 출처를 강제 |
| 비교 대상 | 그때그때 다른 나라 | **일본 고정 + 미국 보조**로 못박음 |
| 재현성 | 운에 맡김 | 다시 만들어도 동일 |

PRD의 가치는 **재현성**이에요. 1-4에서 나리님이 돌린 브리프가 매번 같은 형태로 나온 건 우연이 아니라, 이 명세가 미리 적혀 있었기 때문입니다.

## [개념] 리서치 봇 PRD가 답하는 5가지

- **ⓐ 누구를 위해** — 이 브리프를 읽는 사람은 누구인가? (시니어 시장을 검토하는 기획·사업 담당)
- **ⓑ 무엇을** — 어떤 주제를 다루나? (인구구조 변화에 따른 시니어 소비·비즈니스·트렌드)
- **ⓒ 어떤 소스로** — 어디를 뒤지나? (국내 공공통계·업계 매체 / 일본 정부 백서·업계 자료 / 미국 조사기관)
- **ⓓ 어떤 형식으로** — 결과가 어떤 모양이어야 하나? (국내·해외 2단 비교 → 시사점 → 출처 → 미확인)
- **ⓔ 어떤 품질 기준으로** — 무엇을 지켜야 "믿을 만한 브리프"인가?

## [개념] 우리 봇의 PRD 한눈에

1-4에서 나리님이 돌린 봇에 **실제로 적혀 있는** 내용이에요.

| 항목 | 내용 |
|---|---|
| **도메인** | 인구구조 변화에 따른 시니어 소비·비즈니스·트렌드 |
| **읽는 사람** | 시니어 시장 진입·확장을 검토하는 기획/사업 담당자 |
| **조사 소스** | 국내 공공통계·정부부처·업계 매체 / 일본 정부 백서·업계 자료 / 미국 조사기관 (→ [부록 A](/appendix#a-리서치-소스-지도)) |
| **비교 축** | **일본 고정**(시차 렌즈) + **미국 보조**(규모·자본) |
| **해석 렌즈** | 인구 피라미드 · 액티브/케어 시니어 구분 · 일본 선행 시차 |
| **출력 형식** | 국내·해외 2단 → 💡 시사점 → 📎 출처 → ⚠️ 미확인 → 💬 다음 질문 |
| **품질 기준** | 수치엔 **📎 출처(매체·발행일)** · 확인 못 하면 **⚠️ 미확인** · **지어내기 금지** |
| **안전 정책** | 투자·의료 판단은 단정하지 않고 전문가 확인 권유 · 추정은 "추정"이라 명시 |

**품질 기준 칸이 이 PRD의 심장**입니다. 이게 없으면 봇은 그냥 말 잘하는 챗봇이에요.

## [개념] 품질 기준 — 세 줄이면 됩니다

> 1. 모든 수치·주장에 **📎 출처(매체명 + 발행일)** 를 붙인다.
> 2. 확인하지 못한 항목은 **⚠️ 미확인**으로 분리해 표시한다.
> 3. 근거가 없으면 **지어내지 않는다.** 추정이면 "추정"이라고 쓴다.

리서치는 틀리면 **사업 판단이 틀어집니다.** 시장 규모를 한 자릿수 잘못 읽으면 사업 계획 전체가 흔들려요. 그래서 이 봇의 원칙은 하나예요 — **근거 없는 단정보다 "모른다"가 낫다.**

::: tip 발행일을 왜 같이 적게 했을까요
시니어 시장은 **빠르게 변합니다.** 3년 전 기사의 "시장 규모 O조 원"을 오늘 숫자처럼 쓰면 곤란해요. 그래서 매체명만이 아니라 **발행일**까지 붙이게 해뒀습니다. 브리프를 읽으실 때 날짜부터 보시면, 그 숫자를 얼마나 믿을지 바로 판단하실 수 있어요.
:::

## [개념] 이 PRD는 어디에 있나 — `CLAUDE.md`

지금까지 본 명세는 **실제로 `CLAUDE.md`라는 파일 하나에 적혀 있어요.**

`CLAUDE.md`는 클로드 코드가 **매 세션마다 자동으로 읽는** 프로젝트 설정 파일이에요. 나리님이 따로 말하지 않아도 항상 배경에 깔립니다. 1-4에서 브리프가 **매번 같은 형태로** 나온 이유가 이거예요.

**CLAUDE.md 없이:**

> "나는 시니어 시장을 보는 기획자야. 국내랑 일본을 비교해서 조사하되, 시차는 같은 지표에 도달한 연도로 계산해서 몇 년인지 밝혀줘. 수치엔 출처랑 발행일을 붙이고, 확인 안 된 건 미확인이라고 표시해줘. 그리고…"
>
> → **매번 새 대화마다 같은 설명을 반복**해야 합니다.

**CLAUDE.md 있으면:**

> "시니어 여행 시장 조사해줘"
>
> → 클로드가 이미 맥락을 알고 있어서 **바로 시작**합니다.

> `CLAUDE.md`는 프로젝트의 **"헌법"**과 같습니다. 개별 프롬프트보다 우선 적용되고, 명시적으로 고치지 않는 한 계속 유지돼요.

### CLAUDE.md에 담으면 좋은 것

- 프로젝트 개요와 목적
- **PRD** — 방금 본 그 명세 (조사 소스 · 비교 축 · 출력 형식 · 품질 기준)
- 용어 규칙 (예: `ALWAYS '시니어'가 아니라 나이대·거주형태까지 좁힐 것`)
- 톤앤매너
- **금지 사항** (예: `NEVER 출처 없는 수치를 쓰지 말 것`)

### 직접 쓰지 않아도 돼요

파일을 열어 편집하실 필요 없어요. 클로드 코드와 대화하다가 **이 한 줄**이면 됩니다.

```
지금까지의 내용을 CLAUDE.md에 저장해줘
```

나중에 나리님이 **다른 프로젝트**를 시작하실 때는 이것도 있어요.

```
/init
```

::: tip 이게 오늘 배우는 것 중 가장 오래 쓰실 겁니다
시니어 리서치 봇을 쓰지 않게 되더라도, **"반복 설명을 CLAUDE.md에 넣어둔다"**는 습관은 클로드 코드를 쓰는 내내 유효해요. 새 프로젝트를 시작할 때마다 제일 먼저 하시면 됩니다.
:::

## [개념] 이 PRD를 언제 쓰나

지금은 봇에 **이미 적용된 상태**예요. 나리님이 PRD를 새로 쓰실 일은 오늘 없습니다.

그럼 왜 알아둘까요? **나중에 봇을 고치고 싶어질 때 어디를 봐야 하는지**가 여기에 있기 때문이에요.

| 고치고 싶은 것 | PRD에서 손댈 칸 |
|---|---|
| "일본 말고 대만·싱가포르도 보고 싶다" | 비교 축 |
| "브리프가 너무 길다, 반으로 줄여줘" | 출력 형식 |
| "이 매체는 신뢰 안 해, 빼줘" | 조사 소스 |
| "추정이어도 좋으니 숫자를 더 달라" | 품질 기준 (⚠️ 신중히) |

어느 파일의 어디를 고쳐야 하는지는 [부록 B](/appendix#md-hierarchy)에 정리해뒀어요.

::: tip [체크포인트] 여기까지 잡으셨다면
- PRD = **만들 것을 명확히 적은 지시서** (모호한 지시 → 명확한 명세 → 재현성)
- 리서치 봇 PRD = ⓐ대상 ⓑ주제 ⓒ소스 ⓓ형식 ⓔ품질 기준
- 품질 기준 = **📎 출처(매체+발행일) · ⚠️ 미확인 · 지어내기 금지**
- **이 명세가 사는 파일 = `CLAUDE.md`** — 매 세션 자동으로 읽히는 프로젝트 "헌법"
- 직접 쓰지 않아도 됨 → **`"지금까지의 내용을 CLAUDE.md에 저장해줘"`** 한 줄
- 봇을 고치고 싶으면 → **PRD의 해당 칸**을 찾아 고친다
:::
