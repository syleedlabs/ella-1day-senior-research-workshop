# 2-2. PRD (제품 요구사항 문서)

::: tip Step 6 / 8 · Part 2
1-4에서 브리프가 **매번 같은 형태로** 나온 게 우연이었을까요? 아니에요. 봇 뒤에 **PRD**라는 지시서가 깔려 있었거든요.

그 지시서를 열어보고, 나중에 나리님이 직접 만드는 법까지 봐요. 그리고 이 명세가 실제로 어디에 사는지 — 파일 이름이 `CLAUDE.md` 입니다.
:::

## [개념] PRD(Product Requirements Document)란?

AI에게 이렇게 말한다고 해봅시다.

> "시니어 시장 리서치 봇 하나 만들어줘."

만들긴 만듭니다. 그런데 나오는 건 **인터넷 평균치 챗봇**이에요. 출처도 없고, 국내·해외 비교도 없고, 모르는 걸 모른다고 하지도 않습니다. 이유는 하나 — **지시가 모호했기 때문**이에요.

AI는 마음을 읽지 못합니다. 머릿속 그림이 아무리 선명해도 **적어주지 않은 것은 만들어지지 않아요.**

> **PRD**는 AI 에이전트에게 주는 **상세 업무 지시서**예요. "무엇을 해야 하는지"를 정확하게 전달합니다.

담기는 건 여섯 가지입니다.

| 항목 | 역할 | 우리 봇의 예시 |
|---|---|---|
| **목적** | 이 시스템이 왜 필요한지 | "시니어 시장을 국내·해외 교차로 조사해 판단 재료를 만든다" |
| **목표 지표** | 성공을 어떻게 측정할지 | "모든 수치에 출처 표기 · 국내·해외 양쪽 최소 1개 소스" |
| **에이전트 구성** | 누가 어떤 역할을 맡는지 | "비교 브리프 · 기회 카드 · 주간 리포트 + 임시 조사원·검수자" |
| **파이프라인** | 작업이 어떤 순서로 흐르는지 | "주제 접수 → 국내·해외 동시 조사 → 시차 해석 → 검수 → 저장" |
| **입출력 정의** | 무엇을 넣고 무엇이 나오는지 | "시니어 주제 한 줄 → 국내·해외 비교 브리프 md" |
| **품질 기준** | 어떤 기준을 지켜야 하는지 | "📎 출처 필수, ⚠️ 미확인 라벨, 지어내기 금지" |

PRD의 가치는 **재현성**이에요. 1-4에서 나리님이 돌린 브리프가 매번 같은 형태로 나온 건 우연이 아니라, 이 명세가 미리 적혀 있었기 때문입니다.

## [개념] 우리 봇의 PRD 살펴보기

1-4에서 나리님이 돌린 봇에 **실제로 적혀 있는** 내용이에요.

| 항목 | 내용 |
|---|---|
| **1. 개요** | **목적**: 인구구조 변화 속 시니어 시장을 국내·해외 교차로 조사<br>**핵심 가치**: 탭 스무 개 열고 반나절 → **몇 분** |
| **2. 전략 및 목표** | 읽는 사람: 시니어 시장 진입·확장을 검토하는 기획/사업 담당자<br>잘했다의 기준: 출처 100% 표기 · 국내·해외 양쪽 최소 1개 소스 · **시차 표현 포함** |
| **3. 에이전트 팀** | **비교 브리프**(조사→해석) · **기회 카드**(사업 언어로 번역) · **주간 리포트**(한 주 훑기)<br>+ 임시 작업자: 국내 조사원 · 해외 조사원 · 검수자 |
| **4. 파이프라인** | 주제 접수 → **국내·해외 동시 조사** → 시차 계산·해석 → 검수 → `output/` 저장 |
| **5. 품질 기준** | 📎 출처(매체+발행일) · ⚠️ 미확인 라벨 · 지어내기 금지 · 국내/해외 수치 혼동 금지 |

### 봇의 판단 기준도 PRD에 들어 있어요

에이전트가 **스스로 결정**하려면 기준이 필요합니다. 우리 봇엔 이런 게 박혀 있어요.

| 무엇을 | 어떻게 정해뒀나 |
|---|---|
| **비교 대상국** | **일본 고정**(시차 렌즈) + **미국 보조**(규모·자본). 임의로 안 바꿈 |
| **해석 렌즈** | 인구 피라미드 · 액티브/케어 시니어 구분 · 일본 선행 시차 |
| **소스 우선순위** | 공식 통계 > 정부 기관 > 업계 리포트 > 언론 기사 (→ [부록 A](/appendix#a-리서치-소스-지도)) |
| **출력 형식** | 국내·해외 2단 → 💡 시사점 → 📎 출처 → ⚠️ 미확인 → 💬 다음 질문 |
| **안전 정책** | 투자·의료 판단은 단정하지 않고 전문가 확인 권유. 추정은 "추정"이라 명시 |

**품질 기준 칸이 이 PRD의 심장**입니다. 이게 없으면 봇은 그냥 말 잘하는 챗봇이에요.

## [개념] 품질 기준 — 세 줄이면 됩니다

> 1. 모든 수치·주장에 **📎 출처(매체명 + 발행일)** 를 붙인다.
> 2. 확인하지 못한 항목은 **⚠️ 미확인**으로 분리해 표시한다.
> 3. 근거가 없으면 **지어내지 않는다.** 추정이면 "추정"이라고 쓴다.

리서치는 틀리면 **사업 판단이 틀어집니다.** 시장 규모를 한 자릿수 잘못 읽으면 사업 계획 전체가 흔들려요. 그래서 이 봇의 원칙은 하나예요 — **근거 없는 단정보다 "모른다"가 낫다.**

::: tip 발행일을 왜 같이 적게 했을까요
시니어 시장은 **빠르게 변합니다.** 3년 전 기사의 "시장 규모 O조 원"을 오늘 숫자처럼 쓰면 곤란해요. 그래서 매체명만이 아니라 **발행일**까지 붙이게 해뒀습니다. 브리프를 읽으실 때 날짜부터 보시면, 그 숫자를 얼마나 믿을지 바로 판단하실 수 있어요.
:::

## 클로드 코드에게 PRD를 요청하는 방법

PRD를 나리님이 직접 쓰실 필요는 없어요. **클로드 코드에게 만들어달라고 하면 됩니다.**

```
나는 [자동화하고 싶은 업무]를 하고 있어.
현재는 [현재 작업 방식]으로 진행하고 있는데,
이걸 자동화하기 위한 PRD를 작성해줘.
```

나리님 일로 채우면 이렇게 돼요.

```
나는 시니어 시장 신사업을 검토하는 일을 하고 있어.
현재는 통계청 자료 열고, 일본 사례 찾고, 뉴스 뒤지는 걸 매번 손으로 하는데,
이걸 자동화하기 위한 PRD를 작성해줘.
```

::: tip 더 좋게 만드는 한 줄
PRD를 요청하실 때 [부록 C-1](/appendix#interview)의 **인터뷰 프롬프트**를 앞에 붙이면 훨씬 정확해져요.

```
바로 만들지 말고, 제가 뭘 원하는지 이해될 때까지 저를 인터뷰해주세요.
```

클로드가 *"결과를 파일로 저장할까요?"*, *"어떤 소스를 신뢰하세요?"* 같은 걸 먼저 물어봅니다. 답하다 보면 **나리님 요구사항이 정리돼요.**
:::

::: tip 오늘은 안 하셔도 돼요
우리 봇의 PRD는 **이미 적용된 상태**입니다. 이 방법은 나중에 **다른 자동화를 만들고 싶어지실 때** 쓰세요.
:::

## [개념] PRD와 `CLAUDE.md`의 관계

지금까지 본 명세는 **실제로 `CLAUDE.md`라는 파일 하나에 적혀 있어요.**

`CLAUDE.md`는 클로드 코드가 **매 세션마다 자동으로 읽는** 프로젝트 설정 파일이에요. 나리님이 따로 말하지 않아도 항상 배경에 깔립니다. 1-4에서 브리프가 **매번 같은 형태로** 나온 이유가 이거예요.

**CLAUDE.md 없이:**

> "나는 시니어 시장을 보는 기획자야. 국내랑 일본을 비교해서 조사하되, 시차는 같은 지표에 도달한 연도로 계산해서 몇 년인지 밝혀줘. 수치엔 출처랑 발행일을 붙이고, 확인 안 된 건 미확인이라고 표시해줘. 그리고…"
>
> → **매번 새 대화마다 같은 설명을 반복**해야 합니다.

**CLAUDE.md 있으면:**

> "시니어 여행 시장 조사해줘"
>
> → 클로드가 이미 맥락을 알고 있어서 **바로 시작**합니다.

> `CLAUDE.md`는 프로젝트의 "**헌법**"과 같습니다. 개별 프롬프트보다 우선 적용되고, 명시적으로 고치지 않는 한 계속 유지돼요.

### CLAUDE.md에 담으면 좋은 것

- 프로젝트 개요와 목적
- **PRD** — 방금 본 그 명세 (조사 소스 · 비교 축 · 출력 형식 · 품질 기준)
- 용어 규칙 (예: `ALWAYS '시니어'가 아니라 나이대·거주형태까지 좁힐 것`)
- 톤앤매너
- **금지 사항** (예: `NEVER 출처 없는 수치를 쓰지 말 것`)

### 직접 쓰지 않아도 돼요

파일을 열어 편집하실 필요 없어요. 클로드 코드와 대화하다가 **이 한 줄**이면 됩니다.

```
지금까지의 내용을 CLAUDE.md에 저장해줘
```

나중에 나리님이 **다른 프로젝트**를 시작하실 때는 이것도 있어요.

```
/init
```

::: tip 이게 오늘 배우는 것 중 가장 오래 쓰실 겁니다
시니어 리서치 봇을 쓰지 않게 되더라도, "**반복 설명을 CLAUDE.md에 넣어둔다**"는 습관은 클로드 코드를 쓰는 내내 유효해요. 새 프로젝트를 시작할 때마다 제일 먼저 하시면 됩니다.
:::

## [개념] 이 PRD를 언제 쓰나

지금은 봇에 **이미 적용된 상태**예요. 그럼 왜 알아둘까요? **나중에 봇을 고치고 싶어질 때 어디를 봐야 하는지**가 여기에 있기 때문이에요.

| 고치고 싶은 것 | PRD에서 손댈 칸 |
|---|---|
| "일본 말고 대만·싱가포르도 보고 싶다" | 비교 대상국 |
| "브리프가 너무 길다, 반으로 줄여줘" | 출력 형식 |
| "이 매체는 신뢰 안 해, 빼줘" | 소스 우선순위 |
| "추정이어도 좋으니 숫자를 더 달라" | 품질 기준 (⚠️ 신중히) |

어느 파일의 어디를 고쳐야 하는지는 [부록 B](/appendix#md-hierarchy)에 정리해뒀어요.

::: tip [체크포인트] 여기까지 잡으셨다면
- PRD = AI에게 주는 **상세 업무 지시서** (목적·목표지표·에이전트 구성·파이프라인·입출력·품질 기준)
- **1-4에서 돌린 봇 뒤에 이 PRD가 있었다**는 걸 이해함
- 품질 기준 = **📎 출처(매체+발행일) · ⚠️ 미확인 · 지어내기 금지**
- **클로드 코드에게 PRD를 요청하는 방법**을 안다 (+ 인터뷰 프롬프트를 앞에 붙이면 더 정확)
- **이 명세가 사는 파일 = `CLAUDE.md`** — 매 세션 자동으로 읽히는 프로젝트 "헌법"
- 직접 쓰지 않아도 됨 → **`"지금까지의 내용을 CLAUDE.md에 저장해줘"`** 한 줄
:::
