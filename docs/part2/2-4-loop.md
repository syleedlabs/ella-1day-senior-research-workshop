# 2-4. 루프 엔지니어링

::: tip Step 8 / 8 · Part 2
마지막 챕터예요. 1-4에서 남겨둔 질문 — *"주간 리포트가 매주 월요일 아침에 알아서 돌게 하려면?"* — 의 답이 여기 있습니다.

[2-3](/part2/2-3-harness)의 하네스가 **한 번 시켰을 때** 제대로 나오게 하는 구조였다면, 루프는 **여러 번 반복될 때** 제대로 돌게 하는 구조예요. 둘 다 "모델을 혼자 두지 않는다"는 같은 생각에서 나왔습니다.
:::

## [개념] 루프란 무엇인가

지금까지 나리님이 봇을 쓰신 방식은 이래요. 나리님이 커맨드를 치면 → 봇이 일하고 → 결과를 주고 → 끝. 다음에 또 필요하면 나리님이 **다시 칩니다.**

**루프(loop)** 는 이 "다시 치는" 부분을 봇에게 넘기는 거예요.

> **루프** = 에이전트가 **정지 조건을 만족할 때까지** 작업 사이클을 반복하는 것.

중요한 건 "반복"보다 **"정지 조건"**이에요. 언제 멈출지를 정해주지 않으면 루프는 위험합니다. 끝없이 돌거나, 엉뚱한 걸 붙잡고 늘어지거든요.

::: tip 프롬프트 엔지니어링과 뭐가 다른가요
- **프롬프트 엔지니어링** = *무엇을 말할까*를 설계하는 것
- **루프 엔지니어링** = ***무엇을 내가 쥐고, 무엇을 봇에게 넘길까***를 설계하는 것

말을 잘 고르는 문제에서, **일을 어디까지 맡길지 정하는 문제**로 넘어간 거예요.
:::

## [개념] 네 가지 루프 — 무엇을 넘기느냐의 차이

| 루프 | 무엇이 시작시키나 | 언제 멈추나 | 어울리는 일 | 도구 |
|---|---|---|---|---|
| **① 턴 기반** | 나리님의 프롬프트 | 봇이 "다 했다"고 판단할 때 | 짧은 일회성 작업 | [커스텀 스킬](/part1/1-1-intro#terms) |
| **② 목표 기반** | 나리님의 프롬프트 | **목표 달성** 또는 최대 시도 도달 | 종료 기준이 명확한 작업 | `/goal` |
| **③ 시간 기반** | **정해진 시각** | 사람이 취소할 때까지 | 반복 업무 | `/loop`, `/schedule` |
| **④ 프로액티브** | 이벤트·일정 (사람 없음) | 각 작업이 목표를 달성하면 | 반복적이고 잘 정의된 업무 | 위 전부 + 동적 워크플로우 |

**사람이 무엇을 넘기느냐**로 보면 이렇게 정리돼요.

```
 ①  턴 기반      나 ──프롬프트──▶ 봇 ──▶ 끝
                 넘긴 것: 검증 방식 ("어떻게 확인할지"를 봇이 앎)

 ②  목표 기반    나 ──목표+정지조건──▶ 봇 ⟲ 반복 ──▶ 목표 달성 시 끝
                 넘긴 것: 정지 조건 ("언제 그만둘지"를 봇이 판단)

 ③  시간 기반    ⏰ ──▶ 봇 ──▶ 끝     (매주 월요일 8시…)
                 넘긴 것: 트리거 ("언제 시작할지"를 시계가 결정)

 ④  프로액티브   📰 사건 ──▶ 봇 ──▶ 끝  (뉴스가 뜨면…)
                 넘긴 것: 프롬프트 전체 ("무엇을 할지"까지 봇이 판단)
```

아래로 갈수록 **사람 손이 덜 가고, 대신 미리 잡아둬야 할 기준이 많아집니다.**

### ① 턴 기반 — 이미 쓰고 계셨어요

나리님이 커맨드를 치면 시작되고, 봇이 "다 했다"고 판단하면 끝나는 루프예요. 1-4에서 하신 게 전부 이겁니다.

여기서 사람이 넘긴 건 **검증 방식**이에요. "출처를 붙여라, 원문과 대조해라, 확인 못 하면 미확인이라 써라" — [2-3](/part2/2-3-harness)에서 본 **검수 4항목이 바로 그것**입니다. 이걸 매번 말로 하지 않고 봇에 심어뒀으니, 나리님은 주제만 주면 돼요.

> **잘 굴리는 요령**: 검증 기준을 **정성적이 아니라 정량적으로** 써보세요. "잘 조사해줘"(❌)보다 "국내·해외 각 2개 이상 출처"(⭕)가 훨씬 잘 작동합니다.

### ② 목표 기반 — 언제 멈출지를 넘긴다

**목표와 멈출 조건을 함께 주면**, 봇이 그 조건에 닿을 때까지 스스로 반복합니다.

```
/goal 시니어 주거 브리프에서 국내·해외 각 3개 이상 출처를 확보해줘.
5번 시도해도 안 되면 멈추고, 뭐가 안 됐는지 알려줘.
```

::: tip `/goal`이 목록에 안 보이면
클로드 코드 버전에 따라 `/goal`이 아직 없을 수 있어요. 그럴 땐 **그냥 문장으로 말씀하셔도 똑같이 동작합니다.**

```
국내·해외 각 3개 이상 출처를 확보할 때까지 계속 찾아줘.
5번 시도해도 안 되면 멈추고, 뭐가 안 됐는지 알려줘.
```

커맨드가 핵심이 아니라 **"목표 + 정지 조건"을 함께 주는 것**이 핵심이에요.
:::

두 가지가 반드시 있어야 해요.

- **[결정론적](/part1/1-1-intro#terms) 성공 기준** — "출처 3개 이상"처럼 셀 수 있는 것. "좋은 브리프"는 기준이 안 됩니다.
- **명시적 상한** — "5번까지". 이게 없으면 봇이 무한정 매달립니다.

### ③ 시간 기반 — 언제 시작할지를 넘긴다 ⭐

**1-4에서 남긴 질문의 답이 여기예요.** 정해진 시각이 되면 알아서 시작합니다.

| | `/loop` | `/schedule` (클라우드) |
|---|---|---|
| 어디서 도나 | **내 노트북** | **클라우드** |
| 노트북을 꺼도 | 멈춤 | **계속 돎** |
| 대화창을 닫으면 | 멈춤 | 계속 돎 |
| 최소 간격 | 1분 | 1시간 |
| 어울리는 일 | 지금 작업 중인 걸 지켜보기 | **매주 리포트처럼 꾸준한 일** |

주간 리포트는 당연히 `/schedule` 이에요. 월요일 아침에 노트북이 켜져 있으리란 보장이 없으니까요.

::: warning `/loop`는 7일 뒤 자동으로 멈춥니다
`/loop`로 건 반복 작업은 **만든 지 7일이 지나면 마지막으로 한 번 실행되고 스스로 사라져요.** 잊고 방치한 루프가 영원히 도는 걸 막는 안전장치예요.

그래서 *"왜 이제 안 오지?"* 싶으면 **7일이 지난 건 아닌지** 먼저 확인해보세요. 계속 돌려야 하는 일이라면 `/loop` 말고 `/schedule` 을 쓰시면 됩니다.

**멈추고 싶을 땐** — `/loop`가 다음 실행을 기다리는 동안 `Esc` 를 누르면 끝납니다.
:::

```
/schedule 매주 월요일 아침 8시에 /senior-weekly-news 를 실행해서
지난 한 주 국내외 시니어 시장 뉴스를 리포트로 정리해줘.
```

::: tip 실제로 거는 건 워크숍 후에
등록·확인·해제하는 전체 절차는 [부록 D-1](/appendix#schedule-setup)에 정리해뒀어요. 오늘은 **"이렇게 하면 된다"**만 잡고 가시고, 워크숍이 끝난 뒤 편하실 때 거시면 됩니다.
:::

### ④ 프로액티브 — 프롬프트 자체를 넘긴다

가장 멀리 간 형태예요. 사람이 시작시키지 않아도 **이벤트가 생기면** 봇이 알아서 움직입니다.

```
/schedule 매일 아침 시니어 관련 주요 뉴스를 확인해서,
사업 기회로 볼 만한 게 있으면 기회 카드로 만들어두고,
별거 없으면 아무것도 하지 마.
```

마지막 한 줄(*"별거 없으면 아무것도 하지 마"*)이 중요해요. **없는 걸 만들어내지 않게** 하는 정지 조건입니다.

::: warning 여기부터는 천천히
프로액티브 루프는 강력하지만, 기준이 헐거우면 **쓸모없는 결과물이 매일 쌓입니다.** ①~③이 손에 익은 다음에 손대셔도 늦지 않아요.
:::

## [개념] 순서를 건너뛰지 마세요

```
1단계   검증 기준을 글로 쓴다        →  "출처 2개 이상, 오래된 자료는 연도 병기"
   ↓                                    (= 2-3에서 본 하네스의 검수 항목)
2단계   완료 조건을 정한다           →  "이게 채워지면 끝, 안 되면 5번에서 중단"
   ↓
3단계   그때 비로소 일정에 건다       →  "매주 월요일 8시"
```

**하네스를 먼저 세우고 루프를 거는 게 순서**예요. 검증 기준 없이 자동 반복을 걸면 **나쁜 결과물이 자동으로 쌓입니다.** 사람이 매번 보고 있을 땐 이상하면 다시 시키면 되죠. 그런데 자동으로 돌면 아무도 안 보는 사이에 계속 쌓여요.

::: tip 도입 전 세 가지 질문
1. **검증 방식과 기준을 글로 쓸 수 있는가?** — 못 쓰면 아직 ① 턴 기반에 머무를 때.
2. **목표가 충분히 명확한가?** — 애매하면 ② 목표 기반이 무한 반복에 빠져요.
3. **작업 일정이 정해져 있는가?** — 정해져 있어야 ③ 시간 기반이 의미가 있어요.

셋 다 "예"면 자동화할 준비가 된 겁니다.
:::

## [개념] [토큰](/part1/1-1-intro#terms) — 자동으로 돌수록 신경 써야 해요

| 원칙 | 왜 |
|---|---|
| 일 크기에 맞는 모델·기능을 고른다 | 뉴스 훑기에 최고 사양을 쓸 이유가 없어요 |
| 성공·정지 기준을 명확히 한다 | 애매하면 봇이 계속 매달립니다 |
| 크게 돌리기 전에 **파일럿** | 매주 걸기 전에 한 번 수동으로 돌려보세요 |
| 결정론적인 일은 스크립트로 | "파일 이름 바꾸기"에 AI를 쓸 필요는 없어요 |
| **필요 이상 자주 돌리지 않는다** | 시니어 시장은 **하루 만에 안 바뀝니다.** 매일보다 매주가 맞아요 |

사용량은 `/usage`로 확인하실 수 있어요.

## [실습] 내 업무에 어떤 루프가 맞을까

```
/2-4-loop-design
```

봇이 나리님 업무를 몇 가지 물어보고 — 얼마나 자주 하는지, 결과가 맞는지 어떻게 아는지, 정해진 주기가 있는지 — **①~④ 중 어느 루프가 맞는지** 진단해서 프로젝트 폴더의 `LOOP.md`에 정리해줍니다. (나중에 이 파일만 다시 열어보시면 돼요)

::: tip 진단 결과가 "① 턴 기반"이어도 정상이에요
모든 일이 자동화 대상은 아닙니다. **판단이 매번 달라지는 일**은 사람이 쥐고 있는 게 맞아요. 루프 엔지니어링은 "다 자동화하자"가 아니라 **"무엇을 넘기고 무엇을 쥘지 정하자"**니까요.
:::

::: tip [체크포인트] 여기까지 잡으셨다면
- 루프 = 정지 조건을 만족할 때까지 반복. **"정지 조건"이 핵심**
- 네 가지 = ① 턴 기반(검증 위임) ② 목표 기반(정지조건 위임) ③ 시간 기반(일정 위임) ④ 프로액티브(전부 위임)
- **`/loop`는 내 노트북, `/schedule`은 클라우드** — 주간 리포트는 `/schedule`
- **하네스 먼저, 루프는 그다음** — 순서를 건너뛰면 나쁜 결과물이 자동으로 쌓임
- 시니어 시장은 하루 만에 안 바뀐다 — **필요 이상 자주 돌리지 않기**
:::

루프 4분류와 도입 순서는 아래 자료를 바탕으로, 시니어 리서치 봇에 맞게 예시를 다시 썼습니다.

:::

## [정리] 오늘 이후 나리님이 혼자 하실 수 있는 것

체크포인트가 "이해했나요?"라면, 이건 **"할 수 있게 됐나요?"**예요. 아래가 오늘 손에 넣으신 겁니다.

| 이런 상황이 오면 | 이렇게 하시면 됩니다 |
|---|---|
| **시니어 주제 하나를 빠르게 파악해야 할 때** | `/senior-compare-kr-global` — 국내·해외를 동시에 조사해 출처 붙은 비교 브리프를 받는다 |
| **"그래서 뭘 할 수 있나"가 필요할 때** | `/senior-biz-idea` — 조사 결과를 걸림돌까지 적힌 사업 기회 카드로 바꾼다 |
| **시장 흐름을 놓치고 싶지 않을 때** | `/senior-weekly-news` — 직접 부르거나, [부록 D-1](/appendix#schedule-setup)로 **매주 자동 실행**을 걸어둔다 |
| **같은 설명을 또 하고 있을 때** | *"지금까지의 내용을 CLAUDE.md에 저장해줘"* — 다음 대화부터 안 해도 된다 ([2-2](/part2/2-2-prd)) |
| **뭔가 새로 만들고 싶은데 말로 정리가 안 될 때** | *"이해될 때까지 저를 인터뷰해주세요"* — 클로드가 먼저 물어보게 한다 ([부록 C-1](/appendix#interview)) |
| **결과물이 그럴듯한데 미심쩍을 때** | *"가장 약한 근거가 뭐야? 반대 입장에서 반박해봐"* — 검사하는 역할을 따로 부른다 ([부록 C-2](/appendix#practice-tips)) |
| **봇을 고치고 싶어질 때** | 파일을 열지 않고 **말로 부탁한다.** 어디가 고쳐지는지는 [부록 B-3](/appendix#b3) |

::: tip 이 중 하나만 손에 붙어도 성공이에요
일곱 개를 다 쓰실 필요 없어요. **이번 주에 한 번**, 회의 전날 첫 번째 줄만 해보시면 나머지는 필요해질 때 이 표로 돌아오시면 됩니다.
:::
