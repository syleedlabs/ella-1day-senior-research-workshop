# 1부 · 하네스 — 한 번 시켰을 때

## [개념] 하네스란 무엇인가

같은 모델을 써도 결과 품질이 들쭉날쭉했던 경험, 있으실 거예요. 대화가 길어지면 갑자기 성의 없어지거나, 스스로 "완벽하다"며 넘긴 답에 빈틈이 있거나. 모델이 나빠서가 아니라, **모델을 둘러싼 운영 구조**가 그때그때 달랐던 거예요.

> **하네스(harness)** = AI 모델이 혼자서는 잘 못하는 부분을 보완하는 **운영 구조**.

말(馬)에 씌우는 마구(馬具)를 떠올리시면 돼요. 같은 말도 마구를 어떻게 채우느냐에 따라 힘을 제대로 쓰기도, 헛돌기도 하죠. **같은 모델도 어떤 구조 속에서 작동하느냐에 따라 결과가 달라집니다.**

## [개념] 모델 혼자 두면 생기는 두 가지 문제

| 문제 | 무슨 일이 벌어지나 | 리서치에서의 위험 |
|---|---|---|
| **컨텍스트 불안** | 대화가 길어지면 앞 맥락을 잃고 성급히 마무리 | 국내 자료를 잔뜩 읽은 뒤, 일본 수치를 국내 것으로 착각 |
| **자기 평가 편향** | 자기 작업을 객관적으로 못 보고 과도하게 긍정 평가 | 출처를 대충 붙여놓고 "출처 표기 완료"라고 스스로 통과시킴 |

두 번째가 리서치엔 특히 치명적이에요. 사람도 자기가 쓴 글을 검토할 땐 관대해지죠. 모델도 마찬가지라, **"내가 만든 브리프"를 "내가 검사"하면 후하게 봐줍니다.**

## [개념] 해결 — 역할을 셋으로 나눈다

| 역할 | 하는 일 | 우리 봇에서 |
|---|---|---|
| **Planner** (기획자) | 무엇을 어떤 순서로 할지 계획 | 주제를 뜯어보고 국내·해외 어느 소스를 볼지 정함 |
| **Generator** (실행자) | 실제 결과물을 만듦 | 조사 내용을 시차 렌즈로 해석해 브리프를 씀 |
| **Evaluator** (검수자) | 만들어진 결과를 **기준에 따라** 검사 | 숫자가 원문과 맞는지, 출처가 실제로 있는지 되짚음 |

핵심은 **제작자와 검수자를 나누는 것**, 그리고 **검수자에게 명확한 기준을 주는 것**이에요.

## [개념] 우리 봇의 Evaluator = 출처·수치 검수자

리서치 봇의 검수자는 "잘 썼나"를 보는 게 아니에요. 딱 **네 가지**만 봅니다.

| # | 검수 질문 | 무엇을 막나 |
|---|---|---|
| **1** | 모든 수치에 **📎 출처(매체 + 발행일)** 가 붙었나? | 출처 없는 숫자가 사실처럼 읽히는 것 |
| **2** | 그 숫자가 **원문과 실제로 일치**하나? | 단위 착오 (억↔조), 연도 착오, 반올림 왜곡 |
| **3** | **국내 것과 해외 것이 섞이지 않았나?** | 일본 시장 규모를 국내 수치로 옮겨 적는 사고 |
| **4** | 확인 못 한 항목에 **⚠️ 미확인**을 붙였나? | 모르는 걸 아는 척 넘어가는 것 |

::: tip 3번이 이 봇에만 있는 검수 항목이에요
국내·해외를 동시에 조사하는 봇이라, **두 나라 숫자가 섞이는 사고**가 이 봇의 고유 위험입니다. 브리프를 읽으실 때도 여기를 한 번 의심해보시면 좋아요 — *"이 숫자, 국내 건가 일본 건가?"*
:::

## [개념] 왜 리서치엔 검수가 필수인가

리서치 결과는 **틀리면 사업 판단이 틀어집니다.** 시장 규모를 한 자릿수 잘못 읽으면 사업 계획 전체가 흔들리고, 3년 전 숫자를 오늘 것처럼 쓰면 없는 기회를 쫓게 돼요.

가장 위험한 건 **근거 없이 그럴듯한 숫자**예요. 티 나게 틀리면 차라리 낫죠. **그럴듯해서 믿게 되는 게 진짜 위험**합니다.

> **1차 방어선 = 출처 표기.** 수치마다 📎 출처를 붙여 어디서 나온 숫자인지 드러낸다.
> **2차 방어선 = 검수자.** 그 출처가 진짜인지, 원문과 맞는지 스스로 걸러낸다.

강사의 딜 에이전트가 6,862억을 875억으로 바로잡은 것도 정확히 이 2차 방어선이 한 일입니다.

# 2부 · 루프 — 반복해서 돌 때

::: tip 여기서부터가 1-4의 그 질문에 대한 답이에요
> *"주간 리포트가 매주 월요일 아침에 알아서 돌게 하려면?"*

하네스가 **한 번 시켰을 때** 제대로 나오게 하는 구조였다면, 루프는 **여러 번 반복될 때** 제대로 돌게 하는 구조예요. 둘 다 "모델을 혼자 두지 않는다"는 같은 생각에서 나왔습니다.
:::

## [개념] 루프란 무엇인가

지금까지 나리님이 봇을 쓰신 방식은 이래요. 나리님이 커맨드를 치면 → 봇이 일하고 → 결과를 주고 → 끝. 다음에 또 필요하면 나리님이 **다시 칩니다.**

**루프(loop)** 는 이 "다시 치는" 부분을 봇에게 넘기는 거예요.

> **루프** = 에이전트가 **정지 조건을 만족할 때까지** 작업 사이클을 반복하는 것.

중요한 건 "반복"보다 **"정지 조건"**이에요. 언제 멈출지를 정해주지 않으면 루프는 위험합니다. 끝없이 돌거나, 엉뚱한 걸 붙잡고 늘어지거든요.

::: tip 프롬프트 엔지니어링과 뭐가 다른가요
- **프롬프트 엔지니어링** = *무엇을 말할까*를 설계하는 것
- **루프 엔지니어링** = ***무엇을 내가 쥐고, 무엇을 봇에게 넘길까***를 설계하는 것

말을 잘 고르는 문제에서, **일을 어디까지 맡길지 정하는 문제**로 넘어간 거예요.
:::

## [개념] 네 가지 루프 — 무엇을 넘기느냐의 차이

| 루프 | 사람이 넘기는 것 | 우리 봇으로 치면 | 도구 |
|---|---|---|---|
| **① 턴 기반** | **검증 방식** | 1-4에서 하신 그것 — 주제만 주면 봇이 조사·출처확인까지 알아서 | 커스텀 스킬 |
| **② 목표 기반** | **정지 조건** | "국내·해외 각 3개 이상 출처를 확보할 때까지 조사. 5번 시도해도 안 되면 중단" | 대화로 조건 지정 |
| **③ 시간 기반** | **트리거·일정** | **매주 월요일 아침 `/senior-weekly-news` 자동 실행** ← 1-4의 그 질문 | `/loop`, `/schedule` |
| **④ 프로액티브** | **프롬프트 전체** | 시니어 관련 뉴스가 뜨면 알아서 브리프를 만들고 분류해둠 | 전부 + 동적 워크플로우 |

아래로 갈수록 **사람 손이 덜 가고, 대신 미리 잡아둬야 할 기준이 많아집니다.**

### ① 턴 기반 — 이미 쓰고 계셨어요

나리님이 커맨드를 치면 시작되고, 봇이 "다 했다"고 판단하면 끝나는 루프예요. 1-4에서 하신 게 전부 이겁니다.

여기서 사람이 넘긴 건 **검증 방식**이에요. "출처를 붙여라, 원문과 대조해라, 확인 못 하면 미확인이라 써라" — 위 1부에서 본 **검수 4항목이 바로 그것**입니다. 이걸 매번 말로 하지 않고 봇에 심어뒀으니, 나리님은 주제만 주면 돼요.

> **잘 굴리는 요령**: 검증 기준을 **정성적이 아니라 정량적으로** 쓰세요. "잘 조사해줘"(❌)보다 "국내·해외 각 2개 이상 출처"(⭕)가 훨씬 잘 작동합니다.

### ② 목표 기반 — 언제 멈출지를 넘긴다

**목표와 멈출 조건을 함께 주면**, 봇이 그 조건에 닿을 때까지 스스로 반복합니다. 특별한 커맨드가 필요한 게 아니라 **부탁하는 문장에 조건을 넣는 것**이에요.

```
시니어 주거 브리프에서 국내·해외 각 3개 이상 출처를 확보할 때까지 계속 찾아줘.
5번 시도해도 안 되면 멈추고, 뭐가 안 됐는지 알려줘.
```

두 가지가 반드시 있어야 해요.

- **결정론적 성공 기준** — "출처 3개 이상"처럼 셀 수 있는 것. "좋은 브리프"는 기준이 안 됩니다.
- **명시적 상한** — "5번까지". 이게 없으면 봇이 무한정 매달립니다.

### ③ 시간 기반 — 언제 시작할지를 넘긴다 ⭐

**1-4에서 남긴 질문의 답이 여기예요.** 정해진 시각이 되면 알아서 시작합니다.

| | `/loop` | `/schedule` |
|---|---|---|
| 어디서 도나 | 내 노트북 | 클라우드 |
| 노트북을 끄면 | **멈춤** | 계속 돎 |
| 어울리는 일 | 지금 작업 중인 것 지켜보기 | **매주 리포트처럼 꾸준한 일** |

주간 리포트는 당연히 **`/schedule`**이에요. 월요일 아침에 노트북이 켜져 있으리란 보장이 없으니까요.

```
/schedule 매주 월요일 아침 8시에 /senior-weekly-news 를 실행해서
지난 한 주 국내외 시니어 시장 뉴스를 리포트로 정리해줘.
```

::: tip 실제로 거는 건 워크숍 후에
등록·확인·해제하는 전체 절차는 [부록 C-1](/appendix#c1)에 정리해뒀어요. 오늘은 **"이렇게 하면 된다"**만 잡고 가시고, 워크숍이 끝난 뒤 편하실 때 거시면 됩니다.
:::

### ④ 프로액티브 — 프롬프트 자체를 넘긴다

가장 멀리 간 형태예요. 사람이 시작시키지 않아도 **이벤트가 생기면** 봇이 알아서 움직입니다.

```
/schedule 매일 아침 시니어 관련 주요 뉴스를 확인해서,
사업 기회로 볼 만한 게 있으면 기회 카드로 만들어두고,
별거 없으면 아무것도 하지 마.
```

마지막 한 줄(*"별거 없으면 아무것도 하지 마"*)이 중요해요. **없는 걸 만들어내지 않게** 하는 정지 조건입니다.

::: warning 여기부터는 천천히
프로액티브 루프는 강력하지만, 기준이 헐거우면 **쓸모없는 결과물이 매일 쌓입니다.** ①~③이 손에 익은 다음에 손대셔도 늦지 않아요.
:::

## [개념] 순서를 건너뛰지 마세요

```
1단계   검증 기준을 글로 쓴다        →  "출처 2개 이상, 발행일 3년 이내"
   ↓                                    (= 1부에서 본 하네스의 검수 항목)
2단계   완료 조건을 정한다           →  "이게 채워지면 끝, 안 되면 5번에서 중단"
   ↓
3단계   그때 비로소 일정에 건다       →  "매주 월요일 8시"
```

**하네스를 먼저 세우고 루프를 거는 게 순서**예요. 검증 기준 없이 자동 반복을 걸면 **나쁜 결과물이 자동으로 쌓입니다.** 사람이 매번 보고 있을 땐 이상하면 다시 시키면 되죠. 그런데 자동으로 돌면 아무도 안 보는 사이에 계속 쌓여요.

::: tip 도입 전 세 가지 질문
1. **검증 방식과 기준을 글로 쓸 수 있는가?** — 못 쓰면 아직 ① 턴 기반에 머무를 때.
2. **목표가 충분히 명확한가?** — 애매하면 ② 목표 기반이 무한 반복에 빠져요.
3. **작업 일정이 정해져 있는가?** — 정해져 있어야 ③ 시간 기반이 의미가 있어요.

셋 다 "예"면 자동화할 준비가 된 겁니다.
:::

## [개념] 토큰 — 자동으로 돌수록 신경 써야 해요

| 원칙 | 왜 |
|---|---|
| 일 크기에 맞는 모델·기능을 고른다 | 뉴스 훑기에 최고 사양을 쓸 이유가 없어요 |
| 성공·정지 기준을 명확히 한다 | 애매하면 봇이 계속 매달립니다 |
| 크게 돌리기 전에 **파일럿** | 매주 걸기 전에 한 번 수동으로 돌려보세요 |
| 결정론적인 일은 스크립트로 | "파일 이름 바꾸기"에 AI를 쓸 필요는 없어요 |
| **필요 이상 자주 돌리지 않는다** | 시니어 시장은 **하루 만에 안 바뀝니다.** 매일보다 매주가 맞아요 |

사용량은 `/usage`로 확인하실 수 있어요.

## [실습] 내 업무에 어떤 루프가 맞을까

```
/2-3-loop-design
```

봇이 나리님 업무를 몇 가지 물어보고 — 얼마나 자주 하는지, 결과가 맞는지 어떻게 아는지, 정해진 주기가 있는지 — **①~④ 중 어느 루프가 맞는지** 진단해서 `LOOP.md`에 정리해줍니다.

::: tip 진단 결과가 "① 턴 기반"이어도 정상이에요
모든 일이 자동화 대상은 아닙니다. **판단이 매번 달라지는 일**은 사람이 쥐고 있는 게 맞아요. 루프 엔지니어링은 "다 자동화하자"가 아니라 **"무엇을 넘기고 무엇을 쥘지 정하자"**니까요.
:::

- 모델 혼자의 두 약점 = **컨텍스트 불안** · **자기 평가 편향**
- 해결 = **Planner / Generator / Evaluator** 분리
- 우리 봇의 검수 4가지 = ① 출처 붙었나 ② 원문과 맞나 ③ **국내·해외가 섞이지 않았나** ④ 미확인 라벨 붙였나

**루프 (반복해서 돌 때)**
- 루프 = 정지 조건을 만족할 때까지 반복. **"정지 조건"이 핵심**
- 네 가지 = ① 턴 기반 ② 목표 기반 ③ 시간 기반 ④ 프로액티브
- **`/loop`는 내 노트북, `/schedule`은 클라우드** — 주간 리포트는 `/schedule`
- **하네스 먼저, 루프는 그다음** — 순서를 건너뛰면 나쁜 결과물이 자동으로 쌓임
:::
