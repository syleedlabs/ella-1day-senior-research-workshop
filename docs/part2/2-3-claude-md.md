# 2-3. `CLAUDE.md` 활용법

::: tip Step 7 / 8
2-2에서 **무엇을 만들지**(PRD)를 잡았어요.

개별 프롬프트보다 우선 적용되고, 명시적으로 고치지 않는 한 계속 유지되는 **일종의 프로젝트 헌법**인 `CLAUDE.md`에 대해 다뤄봅니다.
:::

## [개념] 매 세션 자동으로 읽히는 규칙

> `CLAUDE.md`는 클로드 코드가 **매 세션마다 자동으로 읽는** 프로젝트 설정 파일입니다.

나리님이 따로 말하지 않아도 **항상 배경에 깔립니다.** 1-4에서 브리프가 **매번 같은 형태로** 나온 이유가 이거예요.

우리 것엔 **규칙 다섯 줄**이 적혀 있습니다.

> 1. 모든 수치·주장에 **📎 출처(매체명 + 발행일)** 를 붙인다.
> 2. 확인하지 못한 항목은 **⚠️ 미확인**으로 분리해 표시한다.
> 3. 근거가 없으면 **지어내지 않는다.** 추정이면 "추정"이라고 쓴다.
> 4. **국내 수치와 해외 수치를 절대 섞지 않는다.**
> 5. 투자·의료 판단은 **단정하지 않는다.**

## [개념] 이 다섯 줄이 있고 없고의 차이

**똑같은 부탁**을 넣었다고 해볼게요.

```
시니어 여행 시장 조사해줘
```

**`CLAUDE.md` 없이 —**

> · 국내 시니어 여행 시장이 빠르게 성장하고 있습니다
> · 액티브 시니어를 겨냥한 상품이 늘어나는 추세입니다
> · 향후 시장 규모는 더욱 확대될 것으로 보입니다

틀린 말은 아닌데 **쓸 수가 없어요.** 어디서 나온 얘긴지 알 수 없고, 일본은 보지도 않았고, 뭘 모르는지도 안 알려줍니다. 회의에 들고 들어갈 수 없는 글이에요.

**`CLAUDE.md` 있으면 —**

> ━━ 국내 ━━
> · 60대 여행자의 몽골 울란바토르 예약률 전년 대비 +233%
>   📎 캐어유 뉴스 (2026-08-05)
>
> ━━ 해외 (일본) ━━
> · (같은 항목을 일본 기준으로)
>
> ⚠️ 미확인
> · 국내 시니어 1인당 여행 지출액 — 공개 자료를 찾지 못함

**부탁은 똑같이 짧았습니다.** 그런데 규칙 다섯 줄이 알아서 걸려서, 출처가 붙고 · 국내와 일본이 갈리고 · 모르는 건 모른다고 나왔어요.

`CLAUDE.md`엔 **비교 축**(일본 고정 + 미국 보조)과 **시차 계산 규칙**([1-4](/part1/1-4-agent)에서 보신 그것), **리서치 소스 우선순위**(어느 기관을 먼저 믿을지)가 함께 들어 있습니다.

**맥락 정보의 우선순위**라든가 **프로젝트의 방향성**에 해당하는 공통적인 개념은 `CLAUDE.md`에 넣어두고 프로젝트를 효율적으로 관리하시면 좋아요.

## [개념] PRD와 `CLAUDE.md`의 관계

둘 다 마크다운 문서지만 **역할이 다릅니다.**

| | **PRD** | **`CLAUDE.md`** |
|---|---|---|
| **한마디로** | 만들려는 것의 **기획서** | 클로드가 참고할 **규칙·안내서** |
| **답하는 질문** | **무엇을** 만들지 (What) | **어떻게** 일할지 (How / Rules) |
| **담는 내용** | 기능 목록 · 사용자 흐름 · 성공 기준 · 제외 범위 | 자주 쓰는 명령어 · 작업 규칙 · 프로젝트 구조 · 금지 사항 |
| **언제 쓰나** | 새로 만들기 **시작하기 전** | 클로드와 대화할 때 **항상 자동 적용** |

::: tip 우리 경우로 바꿔 말하면
**PRD** — *"국내·해외를 교차 조사해 시차를 읽는 리서치 도구를 만든다. 출처 100% 표기가 성공 기준이다."* → **무엇을**

**`CLAUDE.md`** — *"수치엔 매체명+발행일을 붙여라. 확인 못 한 건 ⚠️ 미확인이라 써라. 국내와 해외 숫자를 섞지 마라."* → **어떻게**
:::

**그리고 우리 프로젝트에선 둘이 한 파일에 들어 있어요.** 별도 `PRD.md`를 두지 않고 `CLAUDE.md` 안에 함께 적었습니다 — 3시간짜리 도구엔 파일을 나눌 만큼 분량이 크지 않고, **한 곳만 열면 되는 게 나리님께 편하니까요.**

::: details 나중에 나눠도 됩니다
프로젝트가 커지면 `PRD.md`(무엇을)와 `CLAUDE.md`(어떻게)를 따로 두는 게 일반적이에요. 그땐 `CLAUDE.md`에 *"기능 정의는 PRD.md를 참고"* 한 줄만 적어두면 됩니다.
:::

## [실습] 직접 쓰지 않아도 돼요

파일을 열어 편집하실 필요 없어요. 클로드 코드와 대화하다가 **이 한 줄**이면 됩니다.

```
지금까지의 내용을 CLAUDE.md에 저장해줘
```

새 프로젝트를 시작하실 땐 이것도 있어요.

```
/init
```

클로드가 폴더를 훑어보고 **`CLAUDE.md` 초안을 자동으로 만들어줍니다.**

::: tip 이게 오늘 배우는 것 중 가장 오래 쓰실 겁니다
시니어 리서치 에이전트를 쓰지 않게 되더라도, **"반복 설명을 `CLAUDE.md`에 넣어둔다"** 는 습관은 클로드 코드를 쓰는 내내 유효해요. 새 프로젝트를 시작할 때마다 제일 먼저 하시면 됩니다.

*"어? 이 설명 지난번에도 했는데"* 싶은 순간이 오면, 그때가 바로 넣을 때입니다.
:::

## [개념] 담으면 좋은 것

나리님이 나중에 **다른 프로젝트**에서 쓰실 때의 목록이에요.

| 항목 | 예시 |
|---|---|
| 프로젝트 개요와 목적 | *"시니어 시장을 국내·해외 교차로 조사한다"* |
| **PRD** | [2-2](/part2/2-2-prd)에서 본 그 명세 (조사 소스 · 비교 축 · 출력 형식) |
| 용어 규칙 | `ALWAYS '시니어'가 아니라 나이대·거주형태까지 좁힐 것` |
| 톤앤매너 | *"단정보다 근거. 길게 쓰지 않는다"* |
| **금지 사항** | `NEVER 출처 없는 수치를 쓰지 말 것` |

::: tip [TIP] 금지 사항을 꼭 넣으세요
*"~해줘"* 보다 ***"~하지 마"*** 가 더 잘 지켜집니다. 우리 `CLAUDE.md`도 **지어내기 금지 · 수치 혼동 금지**가 가장 강한 문장이에요.
:::

::: tip [체크포인트] 여기까지 잡으셨다면
- `CLAUDE.md` = **매 세션 자동으로 읽히는** 프로젝트 "헌법"
- 우리 것엔 **다섯 줄의 절대 규칙** + 비교 축 + 시차 계산 규칙 + 소스 우선순위가 들어 있다
- PRD는 **무엇을**(What), `CLAUDE.md`는 **어떻게**(How) — 우리 프로젝트는 둘이 한 파일에 있다
- 담으면 좋은 것 = 개요 · **PRD** · 용어 규칙 · 톤앤매너 · **금지 사항**
- 직접 쓰지 않아도 됨 → **`"지금까지의 내용을 CLAUDE.md에 저장해줘"`** 한 줄
- 새 프로젝트엔 **`/init`**
:::
